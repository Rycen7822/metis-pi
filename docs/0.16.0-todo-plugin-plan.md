### M1 — todo 核心：model + store

`src/todo/model.ts`（纯函数，全部可单测）：
- Task：`{id, title, parentId?, status, blockedBy[], claim?, evidence?, skipReason?,
  createdAt, updatedAt, completedAt?, completedAtTurn?}`。
- **状态机 4 态**：pending | in_progress | complete | skipped + `VALID_TRANSITIONS` 显式表
  （goal-x 用 3 态+currentTaskId；我们选 4 态，理由：并行 subagent 时多个任务在飞，
  单焦点指针表达不了；claimed ⇒ in_progress 由转移规则表达）。
- 派生：父任务显示态由子树推导（子全 complete→complete；任一 in_progress→in_progress）；
  进度 = 叶子完成度 BFS。
- LLM 接口：add 接受**扁平** `[{title, parentId?}]`，扩展端建树；
  `mergeById`（模型重发全量列表按 id 合并不覆盖——goal-x 教训）；
  标题去重校验 `validateDistinctTitles`（错误作为工具结果返回给模型，不抛 UI）。
- blockedBy：悬空/自依赖/DFS 环检测；增量 addBlockedBy/removeBlockedBy API（rpiv）。
- 常量：`MAX_TASKS = 15`（goal-x）；`sanitizeText`（剥 CSI/OSC、bidi，rpiv 可搬）。
- 无变更检测原语：`diffTasks` 逐字段比较（工具层用）。

`src/todo/store.ts`：
- 目录 `<cwd>/.pi/codex-todos/`（env `PI_CODEX_TODO_PATH` 覆盖；**刻意不与
  pi-agent-extensions 的 `.pi/todos/` 同名**，避免双装期互踩）。
- `tasks.json` 单文件事实源（`{version: 1, nextId, tasks[]}`，version 字段第一天就有——
  rpiv「工具名+schema 是不可变 ABI」教训）；原子写 tmp+rename；损坏时改名
  `tasks.json.bak-<ts>` 后空载（doctor 可见）。
- 跨进程写锁：`tasks.lock`（`wx` 原子建、TTL 30min、steal 需确认——pi-agent-extensions
  :938-1016 模式简化版）；进程内 async 互斥。锁只护读-改-写瞬间，不护整个工作期。
- GC：closed 超过 `gcDays`（settings.json，默认 7）清理。
- claim 记录 = Task.claim（长寿命）≠ 写锁（短寿命），两者分离。

完成条件：新增 model/store 单测全绿（tmpdir，绝不写真实 HOME——rpiv 教训）。

### M2 — LLM 接口：tools + commands

`src/todo/tools.ts`：
- `registerTool("todo")`（与 pi-agent-extensions 同名，**部署时需禁用对方的 todos 扩展**；
  registerTool 包 try/catch，撞名时 notify 一次而不是刷屏）。
- actions：list / add / update / complete / skip / reopen / claim / release /
  addBlockedBy / removeBlockedBy。
- complete 门禁（goal-x）：证据非空（evidence 标 UNTRUSTED claim）+ 若有证据文件路径则
  校验存在 + 子树未完成默认 **block**（列出未完成子任务 id+title；可配置 warn）。
- skip 级联 + skipReason 留痕。claim/release 带 `force`（覆盖他人认领）。
- **无变更检测**：update 无实际变化 → 返回 `No change: #3 already matches ...`
  （防模型重试循环——rpiv 教训）。
- schema description 兼任 prompt（8 条 guidance：claim-before-work、complete 单程、
  扁平输入、blockedBy 用增量 API 等）。

`src/todo/commands.ts`：
- `/todos` — 打开 overlay（M4 就绪前先 toggle widget 折叠）。
- `/todos-doctor` — 只读诊断四类故障（坏 JSON/坏账本行/过期锁/孤儿备份），
  修复必须用户确认 + 先复制到时间戳备份目录（goal-x /goal-recovery 模式）。

事件接线（extensions/todo.ts）：session_start（加载 store、若存在未完成任务则
notify「已恢复 N/M」——goal-x 恢复提醒）；tool_execution_end（非错误且 todo 工具 →
requestRender）；ui_prompt_start（turn 计数器 +1，驱动已完成延迟收起）。
compact 成功事件存在与否 M2 确认；若无，依赖 widget 常驻可视 + 工具 description 自愈
（pi-goal-x 的 post-compact 提醒退化方案，记录在案）。

完成条件：工具行为单测（假 pi 驱动，仿现有 test/helpers 模式）。

### M3 — 常驻 widget

`src/todo/widget.ts`（rpiv 工程细则全套）：
- setWidget register-once（`widgetRegistered` 布尔显式管理）；factory 形式注册，
  宿主每次渲染经 factory 取最新快照（goal-x getter 教训）；归零
  `setWidget(key, undefined)`；dispose 第一步注销。
- session_start 时 uiCtx 身份比较，防 /reload 打到死代理（rpiv :51-58）。
- 纯 selector：预算 = maxLines − 1(标题)，溢出再 −1(summary 行)；**先丢已完成、
  再截断未完成**；`+N more (a completed, b pending)`。
- 渲染：glyph 集中表（○ ◐ ✓ ✗，blocked 加 ⚠ 前缀——沿用 pi-codexy 文字呈现归一化）；
  有 blockedBy 才显示每行 #id 前缀；逐行 truncateToWidth；尾部 spacer 行。
- **稳定高度 latch**：首渲染锁行数，头部增长由 padding 收缩吸收（goal-x :364-372）。
- 已完成延迟收起：`completedAtTurn < currentTurn` 纯筛选（磁盘化简化版，不搬 rpiv
  双 Set 状态机）。
- 刷新零轮询：仅 store 写 + todo 工具 tool_execution_end → requestRender。
- `pi.registerShortcut("ctrl+shift+t")` 折叠/展开（KeyId 合法性自检，rpiv :60-91 教训；
  **0.17.1 修订**：折叠语义改为"三行常驻 / 点击展开全部"两级视图——左键单击面板任意一行切换，
  展开态写盘（`widgetExpanded`，替代原 `widgetFolded`），ctrl+shift+t 保留为键盘等价物；
  v1 不提供用户可配键位）。

完成条件：selector 纯函数单测 + identity theme 渲染断言（字符串数组比对）。

## 设计来源（references/ 三方分析，2026-09-19）

- rpiv-todo（外观/widget 蓝本）：register-once、预算 selector、无变更检测、转移表、
  blockedBy 校验、sanitize、事件驱动零轮询、getter factory、稳定高度、spacer、
  identity theme 测试。
- pi-goal-x（长任务推进蓝本）：扁平输入建树、mergeById、父子门禁默认 block、
  派生状态、恢复提醒、doctor 只读诊断、轻量 evidence 防御、一次性提醒。
- pi-agent-extensions todos（持久化/认领蓝本）：文件锁+TTL、front-matter 经验、
  claim/lock 分离、force、GC、命名键位。
- 教训清单：单一事实源（不存三份）、~6 文件规模（不 30 模块）、事件驱动（不轮询）、
  tmpdir 测试、schema 带 version。

## 风险与开放项

1. compact 成功事件名未确认（M2 第一件事枚举 `pi.on` 可用事件）。
2. registerTool 撞名时 pi 行为未确认（M2 用 try/catch + 单次 notify 兜底）。
3. todo 扩展在 pty workspace 自动加载后，既有 stages 的行为回归靠 M5 的 pty 全跑兜底。
