# 历史精简与恢复

condense 先保存可查询原文，再精简请求历史；模型摘要与机会式容量压缩（OCC）按各自门槛触发，Pi 普通手动/容量压缩仍由宿主管理。

## 设置与命令

配置位于 Pi `settings.json.contextPrune`，跟随宿主 agentDir。新安装不自动开启，不覆盖已有值；`/pruner status` 查看，`settings` 修改，`on/off` 启停，`now` 手动处理待摘要批次，`compact` 压缩已摘要调用链。

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| `enabled` / `opportunisticCompaction` | `false` | 自动精简总开关 / 需同时开启总开关的 OCC。 |
| `summarizerModel` / `summarizerFallbackModels` | `default` / `[]` | 主摘要模型 / 按顺序尝试的备用模型列表，最后回退当前会话模型。 |
| `pruneOn` | `agent-message` | 最终回复边界处理，含 goal 中间回复。 |
| `minBatchChars` | `5000` | 剩余语义候选的字符保护；0 仅关闭此保护，不强制模型请求。 |
| `autoBudgetThreshold` | `0.7` | 自动付费摘要的压力准入；另有 300,000-token 上限及原生容量减 16,384 的增长余量。显式 `null` 关闭自动付费摘要，不关闭确定性处理、手动请求或原生容量恢复。 |
| `batchingMode` | `turn` | 按助手工具轮次分组；`agent-message` 合并同一用户任务内的轮次，均按输入预算拆片。 |
| `chainCompression.enabled` / `rollingWindow` | `true` / `3` | 工具结束或回复落盘后，在后台收拢较旧的已结束任务链，保留最近 3 条；0 表示不保留最近链。 |
| `chainCompression.fuseRangeSummary` | `true` | 仅允许手动 `compact` 对满足净收益预算的多批摘要额外融合；自动整理始终不请求二次融合。 |
| `showPruneStatusLine` / `showOccStatusLine` | `true` | 单行精简比例及摘要 token 用量 / 最近 OCC 状态。 |
| `compactionSummaryMaxTokens` | `0` | Pi 原生压缩摘要的额外输出 token 上限；0 沿用 Pi，正整数自定义，仍受 Pi 和模型上限约束。 |

未填写字段采用上述新默认值；已有合法值（包括 `autoBudgetThreshold: null`）不自动改写。总开关和 OCC 仍默认关闭。这不是对个人 settings 的修改。

精简状态与摘要用量合并为一行，例如 `│ prune: ON · 242.1k->87.9k (-64%) · usage: 23039 tokens`。用量为本次会话/分支加载后的摘要输入与输出 token 合计，不含恢复的历史用量；不统计或显示美元费用。

也可直接编辑 `~/.pi/agent/settings.json`（或 `PI_CODING_AGENT_DIR` 下的同名文件），在已有 `contextPrune` 对象中设置 `"compactionSummaryMaxTokens": 32768`；保存后用 `/reload` 或重启 Pi 读取。

可在已有 `settings.json.contextPrune` 中配置摘要回退链（替换为模型注册表中的实际 provider/model-id）：

```json
{
  "contextPrune": {
    "summarizerModel": "provider/primary",
    "summarizerFallbackModels": [
      "provider/fallback-1",
      "provider/fallback-2",
      "provider/fallback-3"
    ]
  }
}
```

保存后 `/reload` 或重启 Pi。主模型不可用时，按数组顺序尝试，全部不可用才使用当前会话模型；默认空列表保留直接回退会话模型的行为。provider 错误、超时、缺少认证或模型未注册会继续下一项；用户取消立即终止，不再尝试。空摘要、输出截断或完整消息超预算不是服务不可用，不触发继续回退，原文保留；所有备用模型共用同一个最终消息预算。列表中的无效值被忽略，重复模型只尝试一次，当前会话模型始终放在最后（若已作为主模型尝试则不重复请求）。

成功后会话内暂时沿用该备用模型，它随后不可用时继续尝试后面的模型；每 10 分钟在后续摘要请求中从主模型重新探测整条链，主模型成功则切回。修改模型链或切换会话模型会清除旧回退状态。工具批次摘要和调用链融合共用这条链；不改变 Pi 原生压缩或 OCC 的模型选择。

`/pruner compaction-summary-limit 32768` 设置摘要输出上限，`/pruner compaction-summary-limit 0` 恢复 Pi 默认，省略数字查看当前值；`/pruner settings` 可选择预设。设置立即生效并保存，自动精简和 OCC 关闭时仍有效，适用于原生手动、阈值、溢出恢复及 OCC。不改变 `reserveTokens`、压缩触发线、普通 agent 回复或工具/链摘要预算。原生拆分压缩中的历史、当前轮摘要各自受限，Pi 的当前轮预算可能更小；这是单次生成上限，不保证合并后的总长度。摘要触及 token 上限导致 `length` 时拒绝发布，保留原历史。

OCC 通过受支持的 `customInstructions` 请求约 **16,384 输出文本 tokens** 的软目标，保留必要事实、不确定性和完整语句；不降低 Pi/模型/provider 的硬上限，也不更改已有 32,768 等自定义上限。当前 Pi 1.0.0 的普通原生压缩既不消费修改后的事件指令，也不经过普通请求的 payload 钩子，故该软目标**不自动注入普通原生手动/阈值/溢出路径**；这些路径保持 Pi 原行为，可用 Pi `/compact` 自定义指令显式请求软目标。不得将 16K 当作统一硬 cap 或可用容量保留值。

`off` 停自动精简，回读和既有图片上限仍可用；完全禁用需过滤入口。外部 pi-condense 改用内置入口时保留 settings、session 和 blobs；检测到已有 context_tree_query 会跳过本入口并警告。

## 候选处理

先验证可见来源与保护状态，分离去重、确定性候选和剩余语义候选。去重先分配独立恢复引用，测量实际占位符，只有本地 proxy 净缩小才授权替换；每次执行的参数、状态和时间戳独立保留，正文按精确 SHA-256 身份匹配，不归一化空白。确定性候选使用真实引用/预览构造完整结果后测量，不需要摘要模型，也不套用付费摘要的 2048/40% 门槛。归档成功本身不授权隐藏。

| 内容 | 安全条件 |
| --- | --- |
| build/test 日志 | 可识别且明确成功；exec_command 须确认退出码 0。运行中、未知、失败、read/search 和复杂未知命令不据此精简。 |
| edit/write 参数 | 完整成功调用组，参数合计至少 5000 字符，输入/输出可恢复且净缩小；保留最近工具交互。失败、未知或受保护组不处理。 |
| Fusion | 保留修改回执、路径和状态，仅精简安全命令日志，nested 分别索引。 |

参数的 5000 字符与 minBatchChars 是独立规则。有效 context_edit 使旧参数替换失效，重载不能改变同一历史结果；编辑后的工具正文和非文本附件不交给该批次摘要路径替换。

### 自动准入与完整摘要预算

`agent-message` 在最终回复边界评估，不再无条件请求付费摘要。准入线为：

```text
min(autoBudgetThreshold × 模型窗口,
    300000,
    Pi 解析的原生容量线 − 16384)
```

仅在 auto-compaction 开启且能解析容量时使用第三项；容量线沿用 Pi 的当前模型/global/project reserve 设置，不猜一个通用 reserve。最终回复尚未落盘时使用该回复已报告的用量，避免误用上一工具轮次的旧用量。低压力候选保持 pending，可在后续真实请求达到压力时重试；手动 `now` 绕过压力线，但不绕过净收益和输出预算。delta/frontier-gap 仅触发评估，不强制付费生成，OCC 的等待/保持仍有优先权。

对每个付费批次，使用去除内部元数据后的 `convertToLlm` 消息 JSON，以 **本地 o200k proxy tokens** 计量：

```text
B       = 实际被替换的原工具结果消息；不借用未改动的助手/调用参数
K       = 实际保留的结果占位符、溢出预览与恢复路径
G       = max(2048, ceil(0.40 × B))
R       = min(6144, floor(B − K − G))
Qtarget = min(6144, 512 + 96 × N)       # N 为本批工具调用数
```

若必要包装的空消息加 256 tokens 高于 Qtarget，则抬高目标；目标超过 R 时不请求模型。否则软目标引导精简，不盲目截断关键事实；**硬预算 R 检查的是实际渲染的整个新摘要消息**，包含正文、内联引用、恢复尾注与消息包装，而非仅检查正文或分别相加 tokenized 片段。别名、来源、模板和预览从预检到发布保持一致，发布前再次验证；满足该预算才有 `B − K − 新消息 >= G` 的本地计量保证。

provider 的输出 cap 与此 proxy 分开：沿用模型窗口/输出的既有 ceiling，不用 proxy R 直接换算 `maxTokens`；隐藏推理仍占用原 provider budget，由模型与推理配置约束。超预算或测量失败保留原结果和 pending，frontier 不跨过缺口；后面的确定性成功可独立提交。原生/OCC 仍使用自己的容量、收益和输出限制，不套用该局部公式。

这些参数来自历史样本校准，不保证未来摘要质量、provider 实际 tokens 或账单收益。高缓存复用时，缩短上下文也可能使前缀变冷，不能把 proxy 节省量等同于 API/经济节省。

摘要输入单批最多 24 次工具调用、65,536 字符，并根据主摘要模型、已注册备用模型和会话回退模型中最小的上下文容量预留提示词、输出空间；长正文保留诊断和首尾。自动和手动路径都在请求前按预算拆批，保留用户任务边界与工具调用顺序；同一工具阶段也可以分片。多调用批次放不下完整参数时拆分，单个超长参数才使用明确标记的原文片段；连最小片段都放不下时记录 input-budget，不请求模型，原文保留。

工具摘要和调用链合并都要求区分已观测结果与助手的推测，保留不确定性，关键代码条件和赋值原样引用；需要据此判断代码行为时，通过恢复接口核对原文。

子代理启动、等待、列表、消息、续跑、回答和中断的管理回执始终保留原文，不交给摘要模型改写状态。子代理正文结果与详细事件历史仍可归档和摘要。其他模型摘要仍是有损记录，不能替代验收或代码原文。

摘要请求最多并发 3 片，结果仍按原顺序归档、落盘和保存处理进度；后面的请求提前完成不会越过前面的片段发布。失败后停止调度并取消后续请求，切换会话或取消操作时取消全部未完成请求；重载只处理尚未提交的部分。并发窗口中已开始的请求可能产生费用。`/pruner now` 显示分批及部分完成状态。agent-message 模式在最终回复时先评估准入；达到压力才开始付费摘要，大输出仍在下一请求前落盘。已报告的完成响应用量包括被预算拒绝、空/截断或 provider 错误的响应；取消或网络失败没有可得用量时不猜账单。失败或预算不足的当前批次保留原文。

旧链整理独立在后台运行，不请求新摘要模型。多条旧链共用一份正文，复用完整已有摘要或已归档的确定性事实，分别保留每条用户原文、最终回复、受保护回执和恢复引用；成员之间的非成员历史不会被一并删除。先补齐归档，正文在当前分支落盘后才允许裁剪；最终有效投影在 Pi 估计与 o200k 本地复核中都必须缩小，否则保留原文。恢复、编辑或分支变化后重新验证。手动 `compact` 不受滚动窗口限制。无论 OCC 是否开启，自动整理均不请求额外链融合。手动 `compact` 的付费融合还须对**完整链消息（含包装、引用与保护正文）**相对于确定性拼接满足同样的 2048/40% 和 6144 proxy 预算，不借用删除调用参数的机械收益；准入不足或输出被拒绝时复用原拼接。

## 原文与分页恢复

归档在会话旁 `<sessionId>-blobs/`，目前不自动 GC。复制/清理 session 时一并考虑 blobs，读取证据不重放操作。

- 进程输出在显示截断/环形丢弃前捕获；小输出可留内存，超长或交付预算丢弃时落盘。每次返回绑定固定字节范围，后续 write_stdin 不改变旧结果范围。
- Pi bash fullOutputPath 在临时文件失效前导入；其他工具只能保存实际收到的内容，不能恢复 RTK/上游已丢文本。
- 原生 nested 使用 execution start/end 与 prepared 参数归档，父结果传播保护、错误、未完成和归档失败。缺失或失败捕获必须标不完整。

context_tree_query 返回历史证据；省略目标先列目录，再分页读取。

| 参数/字段 | 语义 |
| --- | --- |
| `toolCallIds` | 原 ID、短引用或链 block 引用；重复 ID 各次出现分别返回，共享 block 可查询各成员归档。 |
| `parentToolCallId` | 父工具的子归档；与另两个 ID 选择器互斥。 |
| `sourceEntryIds` | 历史来源条目，仅 output；与 toolCallIds 互斥。 |
| `component` | output / arguments；arguments 需指定 toolCallIds。 |
| `maxBytes` | 2048–32768，默认 32768；限制整个 JSON，含元数据/cursor。 |
| `cursor` | 绑定 session、目标内容版本和 component；普通增长可继续，分支切换目标消失则失效。 |
| `complete/eof` / `archiveComplete` | 分页进度 / 捕获完整性，两者不能混用。 |

分页按 UTF-8 安全边界切分，长行可继续，details 只含当前页。恢复保护按用户消息组处理，不把全部历史塞回请求。

## OCC 调度与成本

仅在最终回复后的空闲边界走 Pi 普通摘要路径；等待不计尝试。

- condense/OCC 共用经济等待与保持期；发布、摘要尝试或宿主压缩后，至少 4 次真实工具工作请求，且有效历史增长达到 5000 字符或原历史的 15%（取较大者），才再次自动摘要。零模型调用的旧链整理可独立运行，但与其他历史改写互斥。
- 预热、摘要、纯计划、轮询、失败、近期重复和回读不计工作。保持期不继续移除错误参数/保护读取，恢复页保持稳定；首次启用可能先还原旧占位符。
- goal 只恢复原本欠下的续跑，执行前复核已接受输入、暂停和目标；取消清掉旧续跑，不保证尚未处理输入立即打断维护。

开启 Pi auto-compaction 时，窗口 W、触发线 T=W-reserveTokens、缓冲 B=max(1024,5%×T)。reserveTokens 由 Pi 按当前模型、全局及可信项目设置解析：

- OCC 按 T 的 60% 开始等待、72% 就绪、低于 52% 退出等待；三次真实工具工作后仍未就绪时释放等待，让本地摘要继续。同一请求后来达到 72% 可重新评估，已完成的工具工作仍有效，实际摘要尝试仍最多一次。复用次数按距离 T 的剩余空间估计。例如 W=1M、配置 T=400k，则等待 240k、就绪 288k、退出等待 208k，缓冲 20k。关闭 auto-compaction 时按模型窗口 W 计算经济门槛。

- 距 T 不足 B 时停止经济 OCC，允许本地摘要释放空间；实际用量严格超过 T 时才由原生容量压缩接管，成功或失败后清除让路状态。
- 候选前后均留 2B，含尾部、保护引用、摘要和固定开销；系统提示/工具定义不算可释放历史。
- 手动、宿主阈值和溢出保留原路径；关闭 auto-compaction 关闭容量让路。候选阶段使用宿主实际设置，SDK 仅内存设置未必可用于预检查。

自动 OCC 使用统一的普通输入∶输出∶缓存输入资源权重 **1∶5∶0.1**，不依赖 provider 的美元价格字段。预检按 Pi、模型及自定义设置共同限制的实际摘要输出上限估算候选大小、空间和摘要成本，而非整个 reserve；同时计入保留前缀变冷成本和每次缓存读取可节省的量。取得 4 个有效增长观察后，用最近 4 个不同成功工具轮次中最大的 token 增长量与剩余窗口估计可复用次数，超过回本所需次数才请求摘要。无有效增长观察或收益不足时不试调用模型，手动/必要容量恢复不受经济判断限制。决策记录保存估计与真实摘要用量对应的相对成本；每次外部用户请求最多一次，goal 续跑不重置。这是资源估算，不保证未来任务数量、真实账单或缓存收益。

本地精简后宿主用量未更新时，仅临时抵扣同一次请求中实际估计缩小量的一半；该校正在 OCC 关闭时也有效。已重估 context_edit 不重复抵扣，下一真实请求、压缩或模型变化清除。手动与实际溢出不使用抵扣。

## 保护与失败

metis-occ-protected-v2 按来源保留用户要求、错误、显式保护与当前 goal；旧摘要保留恢复引用，避免递归包装，不从模型正文猜来源。未知格式/手动调用链保守保留，可能因此拒绝候选。

旧区成功归档或普通恢复结果可换精确位置引用，近期尾部与 protectedTools 保留；有效 context_edit 先投影，归档成功不授权隐藏用户、goal 或错误。

摘要变大、保护过大、归档失败、后台进程运行或历史变化均保留上下文；门禁也可拒绝 Pi 普通压缩。失败/取消清理候选并进入保持期，取消清掉欠下的 goal 续跑；安全拒绝后仍有效目标可继续。

## 状态与用量

prune 用量统计本次加载以来额外摘要，重复通知覆盖、切分支重置、未知价格不报金额。OCC 显示 compacting → compacted/cancelled/not compacted，等待和手动/宿主压缩不覆盖状态；隐藏仅关闭标记。

即使摘要候选被拒绝也记录用量；决策记录估计/实际大小和净变化。Footer Σ 使用标准 session 用量；Working 到 settled 后收尾，摘要中不预热，goal 提示以追加消息维持系统前缀。
