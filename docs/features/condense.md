# Condense：历史整理与原文恢复

Condense 用摘要、去重引用或预览替换后续模型请求中的旧工具结果。原始参数和结果仍可从会话归档读取。摘要用于压缩上下文；核实命令、结果或错误时，请读原文。

自动历史整理与空闲整段压缩（OCC）默认关闭。Pi 自身的自动压缩独立于这两个开关。

## 启用与配置

| 命令 | 用途 |
| --- | --- |
| `/pruner settings` | 设置摘要模型、触发方式与保护规则。 |
| `/pruner on`、`/pruner off` | 开关本地历史整理；归档查询始终可用。 |
| `/pruner status`、`/pruner stats` | 查看队列、整理进度与摘要用量。 |
| `/pruner now` | 在 Condense 开启时处理待整理内容。 |
| `/pruner compact` | 整理具备有效摘要的闭合小 chain，忽略 `rollingWindow`。 |

命令保存到全局 TOML 的 `[contextPrune]`。手动编辑后运行 `/reload`。字段见[参数参考](../../metis-pi-config.md#contextprunecondense--occ)。

## 三层分组

| 单位 | 边界 |
| --- | --- |
| Batch | 一次模型请求产生的工具调用和结果。 |
| 小 chain | 一条完整、非空的 assistant 文本开始，到下一条文本、用户输入或 Goal 续跑之前。仅有工具的开头可单独成段。 |
| 大 chain | 从用户输入或 Goal 续跑开始，到下一次输入或续跑之前。 |

完整文本可与工具调用出现在同一条消息里。分段依据完整文本、用户输入和 Goal 续跑；思考、流式片段及工具结果随所属消息处理。`batchingMode = "turn"` 各批次独立；`"agent-message"` 可合并同一小 chain 中的相邻批次。

## 何时整理

默认 `pruneOn = "agent-message"`，在完整可见的回复后评估。`"on-demand"` 也会按上下文压力、工作增长或积压评估。`pending` 表示模型视图仍在使用原文，可能在等待消费确认、近期保护解除、预算或费用条件。

交互终端在当前运行结束、输入队列清空后执行自动付费批次摘要，让工具后的下一次主请求优先运行。新输入会中止后台摘要，原文保持可见。已报告的用量照常计入；等待回执期间保留成本估算。显式 `/pruner now` 和非交互模式会等待摘要结果。

- 大结果可在捕获时落盘，留下预览与引用；`spillThreshold` 默认为 65,536 字符。归档与模型消费分别记录，归档完成后等待消费确认。
- 精确去重保留每次调用的参数、结果引用和执行状态。可识别的成功构建或测试可用本地规则摘录。工具结果也可交给摘要模型。闭合的小 chain 可复用已有的摘要。
- 自动摘要和 chain 整理要求结果已被成功的主模型请求消费。保护范围包括开放的小 chain、最近 32,768 个估算 token、最近 4 轮有效工具工作、配置的工具和路径，以及回读宽限期。`rollingWindow` 默认参考最多 3 个近期闭合的小 chain，并与开放段共用近期 token 预算。手动整理仍须通过保护、归档完整性和实际收益检查。

自动整理小 chain 时，Condense 按替换后实际发送的消息评估缓存断点。如果较前的一段已经可以替换，后续内容又能通过已有摘要或本地规则处理，并且首次请求的预计费用持平或下降，这些段落会一起发布并复用现有摘要。归档失败的段落保留原文，其他通过检查的段落仍可发布。

在同一轮处理中，后续批次的费用基于已经发布的替换计算，缓存改写成本按整轮结算。

### 付费摘要预算

付费压力线取三者中最小值：`autoBudgetThreshold × 模型窗口`、`summaryBudget.maxBudgetWindowTokens`、`max(0, Pi 自动压缩线 − growthHeadroomTokens)`。比例默认为 0.7，上限为 300,000 token，预留量为 16,384 token。Pi 阈值未知时跳过第三项。`autoBudgetThreshold = false` 仅停用自动付费摘要；本地处理、手动整理与 Pi 压缩保持各自设置。

候选原文默认至少 5,000 字符。每次付费替换默认至少净省 2,048 token 且节省 40%，每个 batch 的完整摘要最多 6,144 token（含恢复引用和包装）。归档与摘要均完整且收益达标时发布替换；其余候选保留原文。输入和输出预算见 [参数参考](../../metis-pi-config.md#contextprunesummarybudget摘要预算)。

### 批次组合的后备处理

自动处理时，队列末尾三个独立批次仅因费用条件等待且没有模型请求时，可以再评估一次组合替换。各批次分别生成摘要并满足各自预算；组合后的视图还必须摊回缓存改写和全部摘要费用。发布失败或取消时保留原文，已产生的摘要费用照常计入。自动付费重试要求来源、模型、策略或报价发生变化。

## 缓存与费用

改写输入前缀可能降低下一次请求的缓存命中率。Condense 先估算冷请求和摘要费用，再与保留原前缀的路径比较。已有改写的额外费用处于待摊回状态，或新工作不足时，会推迟下一次改写。同一请求路径的缓存用量证据缺失时，按冷重建做预算；首个正常请求的用量用于校正估算。主请求失败时跳过摘要成本结算，摘要请求失败仍可能计费。

成本结算状态保存在当前会话分支中。模型报价和 Pi 压缩窗口保持一致时，重载会恢复待摊回及待结算的摘要费用，并重新验证缓存。自动和手动摘要在请求前记录预计费用，收到有效用量后结算；等待回执期间保留预估。手动摘要在报价待定时使用有限的备用报价，自动摘要则等待报价。容量应急和手动命令可直接执行。下一次主请求前的多次替换以替换前的输入为基准，缓存重建按一次结算。

普通批次按后续 3 次请求比较，自动大 chain 与共享规则整理按 24 次，有界独立候选最多 32 次。这些数值定义费用预测范围。预测假设每次请求增加 2,000 token、目标缓存命中率为 98%。短任务的后续请求可能不足以摊回成本，账单以提供商为准。

报价依次采用 Pi 模型目录、[models.dev](https://models.dev/) 本地快照、缓存输入与普通输入 1:10 的相对估算。报价快照为 `<agentDir>/cache/metis-model-prices.json`。模型目录或安装版本变化时重新检查；刷新失败可使用已有报价。

### 与 Pi 自动压缩的关系

接近 Pi 压缩阈值且处于暂停线以下时，Condense 可优先整理旧 chain 腾出空间。Pi 自动压缩开启且有效阈值为 `T` 时，上下文达到 `90% × T` 后，Condense 暂停自动整理和 OCC，等待 Pi 压缩。Pi 完成压缩后，上下文进入新的记账窗口。`T` 包含 Metis 配置的 [自动压缩上限](../configuration.md#自动压缩上限)。在途改写发布前，原文保持可见；`/pruner now` 和 `/pruner compact` 仍可使用。

## 摘要模型与故障处理

`summarizerModel = "default"` 使用当前模型，也可填已注册的 `provider/model-id`。认证、可用性、超时或提供商故障时，依次尝试主摘要模型、`summarizerFallbackModels` 和当前模型，跳过重复项。有效且符合预算的摘要才会发布；其他结果保留原文。

摘要模型与备用模型都会收到该批工具参数和结果。跨提供商配置前，请确认允许把这些资料发送给目标模型。

## 原文与分页恢复

通过 [`tool_search`](tool-discovery.md) 发现 `context_tree_query`。首次调用省略选择器可列出证据目录；之后按 ID 读取，例如：

```js
text(await tools.context_tree_query({ toolCallIds: ["t12"], maxBytes: 8192 }));
```

| 参数 | 用途 |
| --- | --- |
| `toolCallIds` | 原始工具 ID、目录短引用（`t12`）或 chain 引用（`b1`）。重复的原始 ID 可对应多条记录。 |
| `parentToolCallId` | 读取父调用下的嵌套结果，包括转录省略的项。 |
| `sourceEntryIds` | 按当前分支的历史、压缩或摘要条目读取。只支持 `output`。 |
| `component` | 默认 `output`；`arguments` 用于读取工具原始参数。 |
| `maxBytes` | 完整 JSON 页的字节预算，含元数据与游标；2,048–32,768，默认 32,768。 |
| `cursor` | 上一页的 `nextCursor`。选择器和 `component` 必须保持一致；游标失效时重新从第一页读取。 |

三类选择器最多使用一种。`eof` 标记分页结束；`archiveComplete` 标记捕获完整性。查询返回执行时保存的内容；当前文件或进程状态需另行查询。回读后会启用 `recoveryGraceTurns` 保护，默认持续 3 次用户输入或 Goal 续跑边界。

归档存放在会话旁的 `<sessionId>-blobs/`。移动、备份或清理会话时请同时处理；归档生命周期独立于压缩。

## 空闲整段压缩（OCC）

同时开启 `contextPrune.enabled` 和 `opportunisticCompaction`，才会在回复已交付且工具空闲时尝试 OCC。每次用户任务或 Goal 续跑最多尝试一次。Pi 自动压缩开启时，OCC 在有效压缩阈值的 60% 开始等待，达到 72% 可就绪，低于 52% 退出等待，达到 90% 交给 Pi 自动压缩。实际执行还取决于工作增长、费用和可释放容量。

OCC 使用 Pi 的普通文字摘要；提供商检查点由 [远端压缩](codex-compaction.md) 管理。`compactionSummaryMaxTokens` 限制普通文字摘要，设为 0 使用 Pi 与模型的限制。`summaryBudget.nativeTargetTokens` 是 OCC 的软目标。压缩取消、失败或摘要无效时保留原历史。
