# Condense：历史整理与原文恢复

Condense 用摘要、去重和归档引用缩短工具历史，减少后续请求反复携带的内容。原始工具参数和结果另行保存，需要时用 `context_tree_query` 读取，不会重新执行工具。

**自动整理和空闲整段压缩（OCC）默认关闭。** 摘要会丢失细节，修改旧历史也可能使前缀缓存失效；上下文变短不一定更便宜。

## 启用与配置

```text
/pruner settings
/pruner on
/pruner status
```

配置保存在全局 `<agentDir>/metis-pi.toml` 的 `[contextPrune]`。`agentDir` 默认为 `~/.pi/agent`，可由 `PI_CODING_AGENT_DIR` 指定。命令直接保存配置；手工修改文件后执行 `/reload`。

| 命令 | 作用 |
| --- | --- |
| `/pruner settings` | 修改摘要模型、触发方式和保护项。 |
| `/pruner on` / `off` | 开关本地历史整理；关闭后仍可读取已归档内容。 |
| `/pruner status` / `stats` | 查看当前配置、整理状态和额外摘要用量。 |
| `/pruner now` | 立即处理 pending；需先开启 Condense。 |
| `/pruner compact` | 整理具备有效摘要的闭合小 chain，忽略 `rollingWindow`。 |
| `/pruner help` | 查看全部子命令。 |

字段、默认值和单位集中在[配置参考](../../metis-pi-config.md#contextprunecondense--occ)。下文说明这些设置如何一起工作。

## 三层分组

分组按消息边界定义，不按 token 数量定义。

| 单位 | 边界 |
| --- | --- |
| 小 batch | 一次主模型请求产生的工具调用及其对应结果。一次请求调用多个工具，仍属于同一批。 |
| 小 chain | 一条完整可见的 assistant 文本回复开始，到下一条文本回复之前；遇到用户或 Goal 续推边界也会结束。 |
| 大 chain | 一次用户输入或 Goal 续推开始，到下一次用户输入或 Goal 续推之前。 |

例如：用户提出任务 → assistant 回复 A → 两轮工具调用 → assistant 回复 B → 一轮工具调用 → 下次用户输入。这里有三个小 batch；A 到 B 之前、B 到下次输入之前各是一个小 chain，整个过程属于同一个大 chain。

- 文本边界取完整消息的非空 `text`，包括同时含文本和工具调用的消息。流式片段、thinking、工具输出和 Condense 派生消息不算。
- 用户输入到第一条 assistant 文本之间的工具工作也有独立起始段。新边界属于下一段，不被上一段吞并。
- 没有下一边界的段仍开放；大任务开放不妨碍整理其中已经闭合的段。
- 闭合不等于模型已读过结果。自动替换还要求后续成功的主模型响应证明这些结果已被消费；失败、中断或截断不算。

`batchingMode="turn"` 保持请求批次独立；`"agent-message"` 可合并同一小 chain 内的相邻批次。单次摘要最多包含 24 个工具调用，输入预算不足时继续拆分；拆分不改变上述语义边界。

## 何时整理

`pruneOn="agent-message"` 是默认值：在完整可见文本回复后评估。`"on-demand"` 允许手动 `/pruner now`，也会在工具轮次按压力、增长或尾部积压设置评估，**并非只允许手动执行**。触发评估不代表一定产生摘要。

不同处理方式各有条件：

| 处理方式 | 是否调用模型 | 主要条件 |
| --- | --- | --- |
| 精确去重 | 否 | 工具名和结果正文完全相同，已有可用记录，替换后确实更小。每次执行仍有独立参数、状态和恢复引用。 |
| 规则摘录（packing） | 否 | 只处理可识别的成功构建、测试等输出，保留首尾及错误、警告、结果行；普通读文件、搜索和任意脚本不套用此规则。 |
| 工具结果摘要 | 是 | 原文归档成功，达到付费摘要压力线，通过局部收益、输入输出预算和缓存费用检查。 |
| 小 chain 整理 | 自动时否 | 复用已有有效摘要和归档；压缩闭合段的工具历史，保留边界文本与恢复引用。 |
| 大输出落盘（spill） | 否 | 单个结果超过 `spillThreshold`，归档后留下预览和引用；默认门槛为 65,536 **字符**。 |

未被模型消费和近期原文的保护适用于自动摘要、packing 和 chain 整理；spill 是单独的大结果落盘规则，不保证把完整大输出先内联给模型一遍。失败调用参数清理、图片上限也各有自己的设置，不能把它们当作 chain 摘要。

### 付费摘要压力与预算

设模型窗口为 `W`，Pi 启用自动压缩后的有效容量为 `T = W − reserveTokens`。默认付费摘要压力线为：

```text
min(0.7 × W, 300000, max(0, T − 16384))
```

无法解析 `T` 时忽略最后一项；用量未知时不自动付费。`summaryBudget.maxBudgetWindowTokens` 改变其中的 300,000，而不是模型窗口或近期原文保护量。`autoBudgetThreshold=false` 关闭自动付费摘要，不关闭手动整理、无模型处理或 Pi 原生压缩。

增长与尾部积压触发仍须通过付费压力和收益检查。剩余待摘要内容不足 `minBatchChars`（默认 5,000 字符）时不请求模型；设为 0 只取消字符保护。

默认单次付费替换至少净省 `max(2048, 被替换结果的40%)` 个本地计数 tokens，完整摘要消息最多 6,144 个，引用、预览和包装也计入。单次摘要的工具历史输入最多 65,536 字符，小窗口模型会进一步收紧。预算不足、摘要为空、截断或实际没有缩小时保留原文。

这些本地计数使用归一化消息的 o200k 分词，与 provider 的输出上限、用量报告和账单不是同一个数值。预算公式见[摘要预算参数](../../metis-pi-config.md#contextprunesummarybudget摘要预算)。

### 近期原文与 chain 选择

自动工具摘要和 chain 整理共同保护以下内容，取各项的并集：

- 最近 **32,768 个估算 tokens** 的原文尾部（`minRecentTokens`）。
- 最近 **4 轮有效工具工作**（`minWorkTurns`）；失败、等待、轮询和原文回读不让较早资料变旧。
- 未消费结果、指定保护工具和路径，以及回读宽限内的内容。开放小 chain 不做整组整理。

`rollingWindow=3` 是近期闭合小 chain 的参考数量，不是无条件保留三整条大链。引用组与开放组共用 `minRecentTokens` 的 token 预算，从近到远选择，下一整组放不下就停止；近期尾部和有效工作保护仍单独成立。

`rollingWindow=0` 只关闭链数参考；其他值同样采用综合保护。显式 `minRecentTokens=0` 同时取消原文最低量和引用组的 token 限额，仍保留工作轮次及其他保护。手动 `now` 使用配置的引用窗口，`compact` 忽略该窗口；两者仍检查指定保护、归档完整性和实际缩小。

## 缓存与费用

自动工具摘要、packing 和 chain 整理共用费用与发布间隔，不能轮流改写来绕过等待。

1. **先算局部收益。** 闭合且已消费、正文为 2,048–65,536 个估算 tokens 的独立请求片段或小 chain，可按自身收益评估。这里的大小只是经济计算档位，不是小 chain 的定义。更大的候选及共享组仍按整体收益检查。
2. **再比较总费用。** 把改写后的首个冷请求单独计入，再估计后续请求：压缩和不压缩两边每次都新增 2,000 tokens，目标缓存命中率同为 98%，缓存量不能超过上一请求已有的长度。计入摘要费用后，压缩侧必须严格更便宜。
3. **限制预测长度。** 通常比较后续 3 次请求；上述有界独立候选最多比较 32 次。32 是费用预测长度，是否整理仍在当前检查点决定。摘要请求发起前按输入和输出上限预留费用，失败或中断而没有用量回执时不视为免费。
4. **等待实际复用。** 发布后须还清估算费用，并新增至少 `max(minGainTokens, 上次净收益/4)` 的有效工作 tokens。有缓存折扣的模型还须在冷请求之后连续 3 次成功主请求达到 90% 实际缓存命中；冷请求本身不计入这三次。

有界候选的绝对收益底线为 `min(2048, chainCompression.minGainTokens)`，比例按候选自身计算；较大的 chain 候选及共享 chain 组则使用默认 8,192 和总上下文 10% 的门槛。工具摘要还须满足前述局部摘要预算，不能用其他片段的节省替一个亏损片段付账。

上下文超过 **256,000** 个估算 tokens 后，有界独立候选只能修改最后 **192,000** 范围内的旧内容，近期保护不降低。256k 是选择策略的分界，不是上下文硬上限，也不是保证达到的目标大小。

费用预测不保证任务还会继续、增长恒定或 provider 保留缓存。短任务可能来不及摊回冷请求和摘要费用；无缓存折扣的模型不要求 90% 命中，但仍检查费用和工作增长。

### 报价来源与刷新

报价依次取自：

1. Pi 已注册模型的价格。先精确匹配，再按受限正则匹配分隔符、日期别名；`mini`、`pro`、`flash` 等型号限定词不能省略，冲突报价不随意选低价。
2. [models.dev](https://models.dev/) 的本地快照，含可识别的上下文阶梯价。
3. 两处均无可靠报价时，按**缓存输入∶普通输入 = 1∶10** 的相对成本估算。这个数不是美元价格，SDK 的缺价零值也不代表免费。

缓存位于 `<agentDir>/cache/metis-model-prices.json`，不按小时或固定过期时间刷新。启动、切换模型和新用户任务时检查 Pi 的 `models-store.json` 与 Metis 安装标记；来源变化后重读目录，必要时后台查询网站。已有快照可继续使用；首次缺价且查询未完成时，自动改写等待报价结果。

`pi update --models` 修改 Pi 模型目录后会触发下一次检查。Metis 正常安装或更新的 `postinstall` 会写刷新标记，因此 `pi update --extensions` 更新 Metis 后也能触发；Metis 无变更且未运行安装脚本、或只更新其他插件时，沿用原快照。失败保留旧报价或回退估价，同一来源版本不反复请求。

## 临近 Pi 原生压缩时

Pi 自动压缩已启用且能解析有效容量 `T` 时，达到 **90% × T** 后停止新增自动改写，包括 pending 摘要、去重、参数整理、spill、chain 和主动 OCC。保留当前前缀，让上下文自然增长到 Pi 的容量压缩线；不会因此挂起 Goal，也不会把自然压缩提前到 90%。

生成期间才进入此区间的候选也要停止发布，已发生的摘要费用仍计入。原文、归档和 pending 保留；已发布的整理结果照常重验与恢复。手动 `now`、`compact` 不受这个自动暂停限制。

## 摘要模型与故障处理

`summarizerModel="default"` 跟随当前会话模型，也可指定已注册的 `provider/model-id`。故障切换按主摘要模型、`summarizerFallbackModels`、当前会话模型的顺序尝试；重复项只保留首次出现的位置。

摘要模型和备用模型会接收该批工具参数与结果，跨 provider 时应按资料权限选择。

认证、模型不可用、超时和 provider 故障可以切换备用模型。空输出、截断、预算不通过不是切换理由，原文继续保留，避免为同一不合格候选反复付费。成功的备用模型会暂时复用，约十分钟后再探测主摘要模型。

## 原文与分页恢复

归档保存在会话旁的 `<sessionId>-blobs/`。备份、移动和清理会话时应一起处理。进程输出会尽量在显示截断前保存，Pi bash 的完整输出文件也会导入；上游已经丢失的内容无法补回。

`context_tree_query` 是延迟加载工具，可用 `tool_search` 搜索并获取参数，再直接调用或在 codemode 中使用。省略选择器先列证据目录，拿到引用后读取所需内容：

| 参数 | 用法 |
| --- | --- |
| `toolCallIds` | 工具原 ID、`t12` 等短引用或 `b1` 等 chain 块引用；重复原 ID 返回各次已索引记录。 |
| `parentToolCallId` | 按父调用读取子调用归档，包括 codemode 界面预览省略的部分。 |
| `sourceEntryIds` | 读取当前分支上的历史消息、压缩或摘要条目，只支持 `output`。 |
| `component` | 默认 `output`；`arguments` 读取原始参数，支持 `toolCallIds` 或 `parentToolCallId`。 |
| `maxBytes` | 每页完整 JSON 的字节预算，含元数据和游标；2,048–32,768，默认 32,768。 |
| `cursor` | 使用上一页的 `nextCursor`，保持相同的选择器和 `component`。 |

三个选择器互斥。分页按 UTF-8 安全边界切分，游标校验会话、当前分支可见性、选择和内容版本；所选来源失效时需重新读取。

`eof` 只表示选定归档已读完；`archiveComplete` 才说明原始捕获是否完整。缺归档、未结束和不完整原因会明确返回。读取到历史输出不代表当前磁盘文件仍相同，也不保证它是进程未经任何过滤的完整日志。

原文回读会触发 `recoveryGraceTurns` 保护，默认持续 3 个大任务边界；assistant 文本回复不会消耗这个宽限。

## 空闲整段压缩（OCC）

OCC 使用 Pi 的普通文字摘要，需要同时开启 `enabled` 和 `opportunisticCompaction`。它在回复结束、没有待交付消息或后台工具占用时尝试，不与远端加密压缩争抢同一请求。

启用 Pi 自动压缩时，OCC 按有效容量 `T` 调度：60% 开始等待，72% 可就绪，低于 52% 退出等待；90% 起交给自然压缩。等待三轮工作仍未就绪会释放本地摘要，不无限占住整理机会。一次用户或 Goal 请求最多实际尝试一次。

发布本地改写、尝试 OCC 或原生压缩后，至少再有 4 轮真实工具工作，且历史增长达到 `max(5000字符, 15%)`，才解除保持期。OCC 用观察到的工作增长估计剩余复用次数，按普通输入∶输出∶缓存输入 = **1∶5∶0.1** 比较费用，且候选必须留足容量余量。这套相对权重不同于局部整理使用的模型报价，不是实际账单。

`compactionSummaryMaxTokens` 限制 Pi 普通文字压缩的输出，覆盖手动、阈值、溢出和 OCC；0 沿用 Pi/模型限制，不限制远端加密检查点。`summaryBudget.nativeTargetTokens` 默认 16,384，只是 OCC 的文字软目标，不改普通 Pi 压缩的提示或触发线。截断、保护内容过多、源变化或预算不足时保留原历史。

## 状态、性能与维护

- `pending` 表示原文仍保留，可能在等压力、费用、近期保护或有效摘要；不是已经删掉但界面没更新。
- 摘要的输入、输出和失败请求用量单列，不混入主 assistant 用量。没有用量回执不表示请求免费。
- 维护结束后只恢复仍有效、尚未完成的 Goal 续推；新输入、暂停和取消状态会重新检查。
- 编辑来源、切分支、改变保护配置或模型后，旧摘要和费用判断需要重新检查。归档存在本身不允许隐藏原文。
- 长会话读取复用活动投影；SDK 的 16 MiB 热正文缓存是内存预算，不是历史截断线，也不是模型上下文上限。实现见 [SDK 补丁说明](../../sdk-patches/pi-1.5.2/README.md)。
- 算法与状态机的验证范围见 [TLA+ 模型说明](../../test/formal/README.md)；模型通过不代表实机延迟或实际账单已验证。

OpenAI/Codex 的加密检查点、OAuth 和跨模型迁移另见[远端压缩](codex-compaction.md)。来源与许可见 [NOTICE](../../NOTICE) 和 [LICENSE](../provenance/condense/LICENSE)。
