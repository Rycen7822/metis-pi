# 历史压缩与恢复

内置 condense 为历史工具调用保存可查询原文，再按规则精简请求历史。模型摘要和机会式容量压缩（OCC）有各自的触发条件；Pi 原生手动压缩与容量压缩仍由宿主控制。

## 开关与迁移

配置保存在 Pi agent 目录的 `settings.json` → `contextPrune`，跟随 `PI_CODING_AGENT_DIR`。使用 `/pruner` 查看或修改；新安装不自动开启，也不覆盖已有设置。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `false` | 自动精简与摘要的总开关 |
| `pruneOn` | `agent-message` | 在最终回复边界处理本轮历史，包括 goal 的中间回复 |
| `minBatchChars` | `1000` | 确定性精简后，剩余正文达到此长度才考虑模型摘要；`0` 关闭此门槛 |
| `opportunisticCompaction` | `false` | 同时启用 `enabled` 后，允许受控 OCC |
| `showPruneStatusLine` | `true` | 显示本次加载以来的额外摘要用量 |
| `showOccStatusLine` | `true` | 显示最近一次 OCC 状态 |

`/pruner off` 停止自动精简，恢复查询和既有图片上限处理仍可使用。彻底卸载入口需按 [配置](../configuration.md) 过滤 `extensions/condense.ts`。迁移外部 pi-condense 时保留配置、session 与 blobs；内置入口在工具发现后检测已有 `context_tree_query`，发现冲突会跳过自身并警告。

## 自动处理流程

每次候选按以下顺序处理，发布前比较完整请求投影的大小，包含恢复引用、占位符及包装。只有整体净缩小才替换历史。

1. 保存原始内容并去重。
2. 对可证明安全的内容执行确定性精简。
3. 对剩余正文应用 `minBatchChars`，满足条件才考虑模型摘要。
4. 校验候选、恢复证据及当前历史版本，再发布结果。

### 确定性精简

| 内容 | 条件与保留范围 |
| --- | --- |
| build/test 输出 | 只处理可识别且明确成功的日志。exec 必须确认退出码为 0；运行中、状态未知、失败日志、read/search 输出和复杂未知命令不据此精简。 |
| `write` / `edit` / `apply_patch` 参数 | 完整成功的已结束调用组，参数至少 **5000 字符**，且输入输出均可恢复、替换后净缩小。保留最近一次工具交互；失败、混合未知状态、受保护内容及 Code 程序不适用。 |
| 融合调用 | 保留修改回执、状态与路径；只对明确成功的可识别命令日志精简。嵌套调用分别建立索引，见 [Action Fusion](action-fusion.md)。 |

参数精简的 5000 字符条件与 `minBatchChars` 是两条独立规则。有效 `context_edit` 会使旧参数替换记录失效；重载不应改变同一历史的结果。

### 模型摘要

单批输入最多 32,768 字符，预算包含调用身份、参数、结果和 assistant 文本。超长正文保留诊断信息及首尾片段；身份和最低片段仍放不下时不调用模型，保留可用的确定性结果或原文。

`agent-message` 模式不会在任务进行中因为压力额外发起摘要调用；超大输出的落盘和捕获仍在下一次请求前完成。手动 `compact-chains` 与 Pi 原生容量处理不受此触发时机限制。

## 原文保存与恢复

### 保存位置与完整性

归档位于 session 文件旁的 `<sessionId>-blobs/`，不在 `.work`。当前没有自动 GC，清理 session 时应一并考虑其引用的 blobs。

- exec 在显示截断及输出环形缓冲丢弃前捕获原文；32 KiB 范围内的完整小输出无需另建文件，超长输出或后续输出预算丢弃仍有归档路径。
- Pi bash 的 `fullOutputPath` 在临时文件失效前导入。其它工具只能归档实际收到的内容，不能还原 RTK 或上游已丢弃的文本。
- 持续执行的 exec 每次结果绑定固定字节区间。后续 `wait` 追加日志不会改变旧结果的恢复范围。
- 融合回执保留修改前缀、状态和路径；嵌套 journal 按已发布字节区间归档，独立于最多 50 条的显示 trace。最终回复会补收遗漏的 turn-end 证据。
- 捕获失败必须标记不完整，缺失文件不能冒充完整原文。读取证据不会重放修改或命令。

### `context_tree_query`

查询结果是历史证据，不作为新指令注入。省略目标时先返回可恢复内容目录，再按需分页读取。

| 参数或结果 | 语义 |
| --- | --- |
| `toolCallIds` | 接受原始调用 ID 或短引用；重复原始 ID 的各次出现分别返回 |
| `sourceEntryIds` | 查询历史来源条目；与 `toolCallIds` 互斥，只能读取 output |
| `component` | `output` 或 `arguments`；读取 arguments 必须指定 `toolCallIds` |
| `maxBytes` | 2048–32768，默认 32768；限制整个 JSON 响应，包含正文、元数据和 cursor |
| `cursor` | 绑定 session、所选记录/内容版本及 component；普通历史增长可继续，分支切换使目标不再存在时失效 |
| `complete` / `eof` | 表示分页读取进度，不能替代原始捕获完整性判断 |
| `archiveComplete` | 表示原文是否完整捕获；缺失或不完整归档会给出明确错误 |

分页按 UTF-8 安全边界切分，超长单行也可继续；details 只包含当前页。恢复保护按用户消息组计算，读取一个目标不会把全部历史重新塞回请求。

## 机会式容量压缩（OCC）

OCC 默认关闭。开启后，它只在最终回复后的空闲边界使用普通 Pi 摘要路径，不另建用户任务。以下门禁共同决定是否尝试；等待本身不计为一次尝试。

### 调度与稳定窗口

- condense 与 OCC 共享等待和保持窗口。接近 OCC 候选时延迟本地发布，原文仍在请求中。
- 本地精简发布、摘要尝试或宿主压缩后，至少经过 **4 次有真实工具工作的请求**，并积累足够新历史，才再次考虑自动处理。预热、摘要、纯文本计划、轮询、失败、近期重复调用及恢复查询不计入；这衡量结构上的工作，不能证明任务取得了语义进展。
- 保持期内不继续清除错误参数或替换受保护文件读取；自动恢复页即使超过普通 grace 也保持稳定。首次启用可能先还原旧占位符，随后进入稳定窗口。
- goal 仅恢复原本欠下的续跑。执行前重新检查用户输入、暂停和目标变化；取消会使旧续跑失效。Pi 在 settled handler 期间可能排队输入，检查的是已接受的输入版本，不承诺尚未处理的输入能立刻中断维护。

### 容量与成本

开启 Pi auto-compaction 时，设模型窗口为 `W`、宿主触发线为 `T = W - reserveTokens`、缓冲为 `B = max(1024, 5% × W)`：

- 距触发线不足 `B` 时停止主动 OCC 和自动 condense 摘要，保留原文并继续归档日志；回到超过 `1.5B` 的余量后才退出让路状态，保持窗口仍有效。
- 候选前后都要留下 `2B` 余量，计入保留尾部、保护引用、摘要和固定用量开销。系统提示与工具定义不能当作可释放历史。
- 手动压缩、宿主阈值压缩及实际溢出沿用原有路径。关闭 auto-compaction 会关闭容量让路，不新增容量配置项。
- 使用既有全局、可信项目及模型设置。已保存设置可供预检查；SDK 仅在内存修改的设置未必可见，候选阶段使用宿主实际设置。

成本门禁要求已知价格，将摘要成本、前缀变冷成本和余量一起估计，以后续 8 次请求为收益假设。每次外部用户请求最多尝试一次，goal 自动续跑不重置次数；这个估计不构成真实缓存收益或账单保证。

本地精简后，若宿主用量尚未更新，只临时抵扣估计缩小量的一半，保留固定开销和额外余量。宿主已重新估算 `context_edit` 时不重复抵扣，下一次真实请求清除此抵扣；手动压缩和实际溢出不使用它。

### 候选保护与失败处理

`metis-occ-protected-v2` 按来源平铺用户消息、显式保护和错误证据，只保留当前 goal。旧摘要作为可恢复来源引用保存，避免递归嵌套保护包装；不从模型正文猜测来源身份。未知旧格式或手动压缩链保守保留，因此可能因预算不足而放弃压缩。

旧区域的成功归档和普通恢复结果可替换为精确出现位置的引用。最近尾部与显式 `protectedTools` 保持原文；成功日志不能冲掉错误证据。保护内容过大时拒绝候选。有效 `context_edit` 先投影到候选，原始用户消息、活动 goal 和失败证据仍受保护；归档成功本身不授权隐藏这些内容。

摘要反而变大、归档失败、后台命令仍在运行、Notebook checkpoint 失败或来源历史变化，都会保留原上下文。opaque Responses/tree/hybrid 路径不主动执行 OCC；普通 Pi 的手动与容量压缩也可能被保护门禁安全拒绝。

容量压缩失败或取消会清理候选并进入保持期，避免立即重试。取消同时清除欠下的 goal 续跑；安全拒绝后，仍有效的 goal 可继续。

## 状态、用量与协作

| 显示或记录 | 口径 |
| --- | --- |
| prune 状态 | 本次扩展加载以来的额外摘要用量；重复通知覆盖，分支切换重置，未知价格不显示金额 |
| OCC 状态 | `compacting` → `compacted` / `cancelled` / `not compacted`；等待或保持期不覆盖上次结果，手动及原生自动压缩不更新此标记 |
| `showOccStatusLine: false` | 只隐藏 OCC 标记，不隐藏宿主进度和错误；UI 立即生效，重载遵从保存值，重新启用可显示最近结果 |
| 决策记录 | 原因、估计与实际大小；摘要返回后即使候选被拒绝，也记录用量。flush 记录参数及输出的净变化与首个受影响消息 |

Footer 的 `Σ` 仍使用标准 session 用量；Working 等到 `agent_settled`、摘要维护结束后收尾。预热与正式请求使用同一历史投影，摘要进行中跳过预热；goal 预算提示用追加消息维持系统前缀稳定。实际服务端缓存收益仍需真实会话测量。
