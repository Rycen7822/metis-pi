# 历史压缩与恢复

metis-pi 内置 pi-condense 2.11.0。沿用已有配置和归档，增加确定性精简、持久输出捕获和统一的最终回复压缩流程。新用户默认关闭压缩；已有 `contextPrune.enabled: true` 继续有效。

## 配置与迁移

使用 Pi agent 目录的 `settings.json` → `contextPrune`，尊重 `PI_CODING_AGENT_DIR`。`/pruner` 查看状态和设置，`/pruner on`、`/pruner off` 切换压缩。不会复制或自动重写已有设置，也不硬编码摘要模型。上游配置说明见 [2.11.0 configuration](https://github.com/jjuraszek/pi-condense/blob/1bdbba695305419e97be179b412b1fb267298d7f/doc/configuration.md)。

如果同时安装了独立 pi-condense，内置入口会在工具发现后检测 `context_tree_query`，跳过自身注册并提示迁移；外部实例继续工作。使用内置版时，先确认更新后的 metis-pi 已安装，再移除独立的 pi-condense 安装项并重新加载。无需删除 `contextPrune`、会话文件或 sidecar。

通过包入口过滤 `"extensions": ["-extensions/condense.ts"]` 可完全禁用内置功能。`metis-pi.json` 的显示层 `enabled` 不控制它。`/pruner off` 仍保留历史回读工具；上游独立的图片数量上限处理保持原行为。

## 自动精简与模型摘要

`pruneOn: "agent-message"` 时，每次最终回复都是处理边界，包括 goal 尚未结束的中间回复。流程为：保留原文与去重 → 尝试确定性精简 → 按精简后尚待处理的工具结果正文判断 `minBatchChars` → 必要时调用摘要模型 → 一次发布结果。当前讨论采用 `minBatchChars: 5000`；小于 5,000 字符跳过模型，达到门槛才调用。沿用已有设置，不自动覆盖上游默认值或用户文件。

确定性精简只处理可识别且成功的 build/test 命令输出，保留开头、结尾及错误/警告等关键行。`exec_command` 必须带有明确的成功退出码；仍运行或状态未知时不精简。未知命令、复杂 shell、失败结果、文件读取与搜索不走这条有损捷径。原始工具结果保留在索引/会话或 sidecar 中，程序补齐恢复引用；模型遗漏引用也不会断开回读路径。模型失败或摘要过长时优先保留有效的确定性精简，否则留下原结果供后续处理。

最终回复模式不再由 condense 的压力提示在任务中途调用摘要模型。已有的超大结果 spill 和执行日志捕获仍在结果首次进入下一次请求前完成；Pi 原生容量兜底保持独立。其他触发模式继续尊重原设置。每次最终回复合并新批次作一次模型决策，已处理历史不会再次自动链压缩；`/pruner compact-chains` 仍可手动使用原有链压缩设置。

## 原文存放位置

归档与 Pi 会话同目录，使用 `<sessionId>-blobs/`，不写入项目 `.work`：

- Codex `exec_command`/`write_stdin`：解码后的命令输出在显示规范化、截断和环形缓冲淘汰前捕获。达到捕获阈值后写入 `exec-<uuid>.log`，未截断的小输出无需额外文件；阈值不高于 32 KiB。实际交付遗漏内容时，即使后续轮询才缩小预算或显示缓冲更小，也会提前落盘。原文保留到交付与重放信息完成，释放会话资源时关闭文件，不删除归档。
- Pi 原生 `bash`：工具提供 `fullOutputPath` 时，将对应内容导入会话归档，避免依赖临时文件寿命。
- [Action Fusion](action-fusion.md)：导入命令原文时保留修改结果和状态前缀；Code/Notebook 按独立 journal 的固定字节范围索引所有融合子调用，不依赖显示 trace。最终回复补扫也会恢复未由 `turn_end` 导入的融合证据。
- 其他工具：保存扩展实际收到的结果；大结果使用 sidecar，小结果使用已有索引/会话。上游工具或 RTK 内部已经丢弃的输出无法补回。

运行中的 exec 日志可以继续增长，每次工具结果固定自己的字节边界，分页期间不会混入后来追加的输出。写入失败明确标记归档不可用或不完整。归档随会话保留，当前没有自动清理策略；清理会话时需一并考虑对应 blobs。

## 缓存行为

后续回复保留已发布压缩块；自动流程不再先发布精简块、随后再用链摘要改写。Codex 的预热与正常请求共用 condense 投影，摘要未完成时跳过预热。goal 的时间和 token 计数移入追加的隐藏状态消息，保持系统指令前缀稳定。

这些措施减少可避免的前缀变化，不保证服务端实际缓存命中率不下降：首次替换已发送的历史、手动链压缩、原生容量压缩等仍可能造成失效。尚未用付费长会话测量真实命中率。

## 分页恢复

工具名称和 `toolCallIds` 保持不变：

```json
{"toolCallIds": ["t12"], "maxBytes": 8192}
```

返回 JSON，其中 `results` 的每条记录包含历史工具、退出错误状态、参数预览、`offsetBytes`、`totalBytes`、精确 `text` 和 `complete`。`source` 区分工具返回与命令归档；`archiveComplete: false` 及 `error` 表示源归档不完整，不能将分页结束当作完整原文。参数预览截短时 `argsTruncated` 为 true。`nextCursor` 非空时，用相同的 `toolCallIds` 和该值作为 `cursor` 继续读取；`eof` 表示整组选择已经读完。重复原始 tool ID 的各次 occurrence 分别返回。

`maxBytes` 约束整个 JSON 文本，包含头部和游标；默认及上限为 32768，最小为 2048。内容不会在 UTF-8 字符中间截断，超长单行也能继续翻页。工具结果 details 仅保留当前页，不复制整份归档。

游标绑定会话和选中的记录；正常会话增长和索引重建不会使它失效，切换到不含相同记录的分支时需重新查询。sidecar 缺失会返回明确错误，不能把预览当作完整原文。恢复的是历史捕获结果：文件可能已变化，RTK 或执行层之前丢弃的内容不能在这里恢复。

恢复宽限期继续按用户消息组保护回读结果；不会因读取一页而主动重新注入整份原始日志。

## 状态、成本与协作

沿用 pruner 的压缩进度状态；显示受已有 `showPruneStatusLine` 控制。最终回复后仍可能等待摘要，Working 的结束继续以 `agent_settled` 为准。摘要失败、取消和会话处理沿用上游机制。

摘要用量在扩展状态中单列为 `prune usage`。数值来自 `cost:external`，是自当前会话加载以来的累计增量；重复通知覆盖显示，不再次相加。切会话/分支清空该显示，未知或零价格不显示美元金额。footer `Σ` 保持原有标准会话 usage 口径。

Pi 原生容量兜底和 goal 继续分别负责容量与续跑。主动 OCC 是下述显式选项；Codex 的额外 context-management/hybrid/native compaction 组合不会自动启用。

## 受控 OCC（可选）

在同一 `contextPrune` 配置中设置 `opportunisticCompaction: true`，并保持 `enabled: true`。默认关闭；启用后普通 Pi 摘要路径会在最终回复后的空闲边界评估一次全局压缩。它不创建新任务。goal 只有原本欠下的续跑才能恢复，执行时重新检查暂停、目标修改及用户输入；用户取消压缩不会恢复旧续跑。

局部 condense 与 OCC 共用缓冲和保持：接近全局候选时暂缓局部发布，已有原文仍可见；任何局部发布、摘要尝试或宿主压缩后，至少经过 4 次真实工具工作请求并新增足够历史才重新评估。等待使用进入/退出不同阈值，不能因门槛波动反复压缩。预热、摘要调用和纯文本计划不增加工作次数。保持期间不做额外的错误参数删除或保护文件重读替换；自动模式持续保留回读页面，避免宽限期到期改写旧前缀。首次从旧模式启用可能把旧回读 stub 恢复为原页，此后表示稳定。

经济候选要求已知模型计费，估算包含摘要开销、一次冷前缀和保守余量；每个外部用户请求最多消费一次主动 OCC 尝试，goal 自动续跑不重置。未来 8 次请求是有界估计，不能保证任务还会持续这么久，更不能据此保证服务端缓存命中率或美元成本改善。保持规则及最终请求内容可离线验证，真实缓存收益尚未实测。

候选从宿主应用 `context_edit` 后的有效投影生成；用户源引用、活动目标、失败/受保护证据、已回读页面及旧全局摘要由程序保留，旧摘要不再次交给模型概括。摘要增大、归档失败、后台命令运行、Notebook checkpoint 失败或生成期间来源改变时保留原上下文。归档准备不等于授权隐藏历史。省略 `context_tree_query` 的 `toolCallIds` 可分页列出证据目录，再按目录引用取回原文；目录中的记录是历史证据，不是新指令。

主动 OCC 首版不支持 opaque Responses compaction、tree/hybrid context management；这些模式继续走原有手动/容量流程，其实际压缩仍触发后置保持。普通 Pi 的手动/容量摘要也经过保护校验，无法安全缩减时会拒绝；不会循环压旧摘要强行腾空间。

Pi 会在 settled handler 执行期间暂存新输入，扩展只能验证已接受的输入版本。此时到达的纠正会在维护后原样处理，旧 goal 续跑凭证随之失效；不是输入一到达便保证中断摘要。
