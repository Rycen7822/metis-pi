# 历史精简、恢复与 OCC

`extensions/condense.ts` 归档工具原文、按有效证据生成精简投影，并提供 `context_tree_query` 回读。**自动精简和 OCC 默认关闭**；读取归档只是读取。

## 启用与配置

使用全局 TOML 的 `[contextPrune]`，命令保存到同一文件；手动编辑后 `/reload`。

```text
/pruner settings
/pruner on
/pruner status
```

| 设置 | 默认值 / 用途 |
| --- | --- |
| `enabled` / `opportunisticCompaction` | `false` / `false`；自动精简 / 空闲时的 Pi 原生摘要。 |
| `pruneOn` / `batchingMode` | `agent-message` / `turn`；完整文本检查点评估 / 按主请求分批。 |
| `summarizerModel` | `default` 跟随会话；也可填已注册的 `provider/model-id`。 |
| `summarizerFallbackModels` | `[]`；有序备用模型，会话模型放在最后。 |
| `autoBudgetThreshold` | `0.7`；付费摘要压力比例，`false` 关闭自动付费摘要。 |
| `minBatchChars` | `5000`；剩余语义候选低于此值不请求模型。 |
| `compactionSummaryMaxTokens` | `0` 沿用 Pi；正数为原生压缩摘要额外输出上限。 |
| `showPruneStatusLine` / `showOccStatusLine` | `true`；精简比例、摘要用量与 OCC 状态。 |

全部字段与合法值见[参数说明](../../metis-pi-config.md)；示例仅供单字段参考。

| 命令 | 操作 |
| --- | --- |
| `/pruner now` / `off` | 立即处理 pending / 停自动精简、保留回读。 |
| `/pruner model <id>[:thinking]` / `thinking` | 选择摘要模型与思考级别。 |
| `/pruner prune-on` / `batching` | 选择触发点与分批粒度。 |
| `/pruner protected-tools` / `protected-paths` | 设置工具名或路径 glob 保护。 |
| `/pruner compaction-summary-limit [n]` | 查看或设置原生摘要 cap，`0` 使用 Pi 默认。 |
| `/pruner recovery-grace [n]` / `dedup on\|off` | 恢复保护窗口 / 精确内容去重。 |
| `/pruner compact` / `stats` / `help` | 整理已关闭调用链 / 用量 / 完整命令帮助。 |

备用链在认证缺失、模型未注册、provider 错误或超时时继续；用户取消立即停止。空、截断或超预算摘要保留原文，原模型照常尝试。成功备用模型暂时复用，每 10 分钟在后续请求中从主模型重试；更换链或会话模型会清除该状态。

## 三层分组

| 层级 | 边界 |
| --- | --- |
| 小 batch | 一次主模型请求的增量输出、连续外层工具调用及对应结果，不是整份历史 prompt。codemode 内部调用不另算主请求。 |
| 小 chain | 从一条完整的真实 assistant 可见文本消息起，到下一条此类消息前；下一条消息属于新组。 |
| 大 chain | 从真实用户输入或带类型的 goal continuation 起，到下一用户/goal 边界前；此边界也截断小 chain。 |

这是包含层级，不是 token 大小等级。text+toolCall 与自己的结果归新小 chain；thinking、空文本、工具正文和程序派生摘要不创建检查点。
首段没有文本时以大任务起点作隐式起点；Native 只保留任务中段时，可以从首个保留文本重新开始，不伪造用户输入。
跨输入边界仍在途的调用不重排；结果仍归原请求，跨界或不完整范围不做整组替换。
`batchingMode=turn` 保持请求分开，`agent-message` 仅在同一文本组内归并；摘要输入预算还可能把它们拆成 chunk，chunk 不是新的语义链。
`pruneOn=agent-message` 在完整可见文本消息结束时评估旧组，包括带工具调用的回复；新回复刚返回或尚未返回的结果不属于旧组。
恢复宽限按真实用户/goal 大任务计龄，不被文本检查点或合成 user 消息消耗。

## 候选与摘要预算

先处理精确去重和可确定的安全结果，再处理语义候选。每次调用保留独立参数、状态、时间戳和恢复引用；归档成功本身并非隐藏授权。

- 明确成功的 build/test 日志可确定性精简，`exec_command` 须确认退出码 0；运行中、失败、未知命令和受保护内容保留。
- 成功 edit/write 组的参数合计至少 5,000 字符、可恢复且净缩小时才精简，保留近期交互。Fusion 保留修改回执，仅整理安全命令日志。
- 有效 `context_edit` 先投影；编辑后的正文、非文本附件、未完成的 nested 证据留在原文里。
- 子代理管理回执保留原文，正文结果和详细历史可归档、摘要。模型摘要有损，验收和代码判断需回读原文。

自动付费许可默认取三者最小值：`0.7 × 模型窗口`、`300000`、`Pi 原生容量线 − 16384`；第三项仅在 auto-compaction 开启且容量可解析时使用。
水位只决定能否付费，不表示应该改写。普通工具摘要和机械packing还须通过近期原文、缓存经济性和新工作间隔检查。
文本检查点延期时只重试当时已捕获的工具occurrence；自动工具替换还须有后续成功主响应的消费证明，不把尚未读过的新结果提前吸入。`now`绕过自动调度门，输出和净收益预算照常生效。

付费替换以去除内部元数据后的消息 JSON 测量本地 o200k proxy tokens：

```text
B = 被替换的原工具结果消息
K = 保留占位符、预览和恢复路径
G = max(2048, ceil(0.40 × B))
R = min(6144, floor(B − K − G))
目标 = min(6144, 512 + 96 × 工具调用数)
```

目标容纳必要包装和至少 256 tokens；超过 R 时不调用模型。R 检查整个新消息，包括正文、引用、尾注与包装。拒绝或测量失败保留原文和 pending，后续成功片段不越过未提交缺口。

proxy 与 provider 计费、输出 token 属于三种口径，provider cap 另按模型与推理配置。缩短上下文可能使缓存前缀变冷，账单收益取决于 provider 实际计费。高级预算参数位于 `[contextPrune.summaryBudget]`。

单批最多 24 次调用、65,536 字符，并按整条模型链最小上下文预留提示与输出。超长轮次拆批，单个超长参数以明确标记的片段进入摘要。最多并发 3 片，按来源顺序归档发布；失败停止调度并取消后续请求，已开始请求仍可能产生费用。

调用链整理复用已有摘要或归档事实，保留真实用户、可见 assistant 文本、第三方 custom、受保护回执和恢复引用；Pi估计与本地复核均须净缩小。
自动维护选择已闭合的小 chain，而非等待整个用户任务结束；还须完整调用对、已消费结果、有效归档与来源证明。右边界完整保留，旧 single/shared 归档仍可重放。
默认近期保护是最近4个有效工具工作轮次与至少32768估算tokens原文的并集；开放小组本身不压，但开放大任务不再锁死其中所有旧工作。
默认`rollingWindow=3`参考近期闭合小 chain，与开放小组共用有限原文参考预算；不足以容纳最近一组时停止扩展，不跳过它额外锁住更老的组。
任意链数值均用综合保护，0只关闭链数参考；显式关闭token保护时链数参考不再受token预算限制。工作集跨小组边界时仍保留整组，不按token截断调用。

2k–64k估算tokens只是有界候选的经济档，不是“小 chain”的定义。合格闭合小组或旧请求 chunk 可按自身净收益评估最多32轮，默认至少净省2k；显式更低底线仍有效。
请求 chunk 须位于已闭合、已消费范围，且独立承担冷前缀与摘要费用，不借其他 chunk 的收益。原三轮聚合门与较大候选的8192tokens/总量10%门保留。
独立链快路每轮从近到远最多尝试三组，只发布一组；未发布时仍可尝试原三轮共享组，不能把共享收益冒充独立过门。
过256k时，局部32轮候选只选最后192k内的旧内容，且不能侵犯近期保护；256k不是总上下文硬上限。大于64k的语义小 chain 仍走较大候选门。
工具摘要还须通过上面的局部proxy预算；chain、chunk和packing共用费用、债务及发布间隔，不另建额度。短组不足以容纳完整摘要时仍保留，不为凑压缩次数降低预算。
普通改写比较同一报价下“不压缩”和“压缩”的总输入费：先单独计算一次冷请求，再预测双方每轮同增2000tokens、目标98%缓存命中；通常三轮，有界局部候选最多32轮。
冷请求的压缩侧最多复用实际保留前缀，缺失部分按普通输入/cache-write较高价计算；对照侧按98%命中。后续请求的缓存量还受上一轮长度限制，不能把新增长算作已缓存。
压缩侧加上摘要费用后须严格更便宜；相等不放行，不再另留10%收益余量，也不把双方共同增长当收益。
一次flush按已发布片段的累计净收益、最早改写点和全部已开始摘要请求费用计算；每个可发布前缀本身都须回本，不赌后续片段必成功。
付费前计入完整提示、原有provider输出上限的估算费用；收到usage后结算，摘要生成后复验实际净收益。失败或中断没有回执时保留预留费用，不假定免费。
发布后还须回本估算归零、新增`max(8192, 上次净收益/4)`有效工作tokens；有缓存折扣时须在冷请求之后连续三次同路由成功主请求达到90%缓存。
98%用于成本预测，不把原有实际回执的90%稳定性门改为98%。还款取实际usage费率与同增长对照净收益的较小估计，低命中不抵债。
收尾回复先观察usage再发布摘要；首个后续请求只结算单列的冷请求，不重复抵扣暖请求收益，也不计入三次预热。预计冷请求盈利须等有效回执才能抵摘要费。
错误、低命中或缺失usage不创造回本/预热，重复回执不重复记账；无缓存折扣且无债务时不增加仅为缓存而设的等待。
价格优先取Pi完整模型列表，先精确provider/型号再用受约束正则匹配格式/日期别名；保留mini/pro/flash等限定词，冲突报价不随意选低价。
Pi无可靠匹配再查models.dev，价格和context阶梯保存在`~/.pi/agent/cache/metis-model-prices.json`，记录来源、查询版本与时间；不按时间过期，也不按小时重试。
启动、切换模型和新用户任务只检查`models-store.json`及Metis安装标记；来源变化后本地重读Pi目录，已有网站快照或实际需要网站价时再后台查询。记录已尝试的来源版本，失败保留旧价或1:10估价，来源再次变化后重试。
冷启动没有可用报价且网站尚未查完时普通改写延期；已有本地快照可先使用并后台刷新。两处均无可靠报价才按缓存输入:普通输入=1:10估算。
普通输入归一为1，不冒充美元价格；未知输出价暂按普通输入价估算，摘要费也使用一致单位。
正常更新/重装Metis会由`postinstall`写`cache/metis-model-prices.refresh`标记；`pi update --models`若修改Pi目录文件，会在下次使用时触发。
这是零SDK补丁的目录变化联动：普通`/model`改了目录也可能触发；Metis无新版本且未执行安装脚本、或只更新其他插件时，不保证触发。主请求不等网站，工具回合不轮询文件。
推导价格按实际usage tokens重新估算，不把原SDK缺价的零费用当免费；models.dev明确列出的免费报价可按零价处理，provider确认的实际费用优先。
已知价使用登记价与usage费用；无缓存折扣模型不强求90%命中，但仍检查费用与增长。模型/配置/分支/Native边界重置估算并重新预热。
旧`maxCostOverhead`不再控制准入，可从个人配置删除。预测回本预算不等于必须等待的轮数；真实还款、增长及三次复用条件仍然有效。
费用预测不保证实际增长、后续请求、缓存TTL/路由或真实账单；任务提前结束仍可能无法摊回冷重建成本。
自动工具批次的近期保护、费用、真实还款和复用间隔不因容量紧张而豁免。
开启Pi auto-compaction且容量可解析时，达到有效容量线`T = 当前模型窗口 − Pi有效reserve`的90%后，
统一暂停自动pending摘要、去重、参数packing、大输出spill、chain及主动OCC，保留当前前缀，等自然增长触发原生压缩。
这不是模型物理窗口的90%，也不提前触发原生压缩或挂起goal续跑；Pi仍仅在实际用量超过T时执行容量压缩。
准备或生成期间才进入该区域的任务也须在发布前停止；已付请求费用仍记账，归档与pending保留，显式手动`now`/`compact`保持原语义。
低于交接线或关闭auto-compaction时沿用原有准入规则；延期重试仍不得吸入活跃任务的新结果。自动维护不发起二次付费融合。
已有持久single/shared视图先重验，不因新工作延期而展开原文。
`chainCompression.enabled`仅开关自动chain；同组的近期保护、增长间隔和成本参数也用于普通自动工具改写。
大输出spill、精确去重、参数精简、OCC及Native保留各自规则，不承诺所有模型决策资料始终完整内联。

## 长会话读取

一次同步投影链共用同一份原生来源和 edit/chain 分析，不把每个 helper 变成新的全量读取。
TUI 准备阶段可使用 SDK 的协作式读取，候选之间让出输入机会；发布前仍同步核对完整正文、策略和生命周期。
Pi 补丁为投影/分支读取保留 16 MiB 内的最新有效正文窗口，不截断记录，也不替代原生压缩。
本地计数只按实际编码输入复用有界结果；预算、收益、保护或来源变化仍按原规则重新判断，不永久跳过曾延期的候选。

## 原文与分页恢复

归档位于会话旁 `<sessionId>-blobs/`，备份、复制与清理时和 session 一并考虑。进程输出在显示截断前捕获，Pi bash 的完整输出及时导入；上游已丢失的内容无法补回。nested 归档保留 prepared 参数、结束状态和不完整原因。

`context_tree_query` 为 deferred 工具，可经 Pi `tool_search` 激活或通过 codemode 调用。省略目标先列目录，再分页读取：

| 参数 / 字段 | 语义 |
| --- | --- |
| `toolCallIds` | 原 ID、短引用或链 block；重复调用分别返回。 |
| `parentToolCallId` | 父工具的子归档；与其他 ID 选择器互斥。 |
| `sourceEntryIds` | 历史来源条目，仅 output；与 toolCallIds 互斥。 |
| `component` | `output` / `arguments`；arguments 需要 toolCallIds。 |
| `maxBytes` | 2048–32768，默认 32768，限制整个 JSON。 |
| `cursor` | 绑定 session、内容版本和 component；目标在分支中消失则失效。 |
| `complete/eof` / `archiveComplete` | 分页进度 / 原始捕获完整性。 |

分页按 UTF-8 安全边界切分。恢复保护按用户消息组生效，回读只补对应片段。

## OCC 调度与成本

OCC 仅在最终回复后的空闲边界使用 Pi 普通摘要，等待阶段与尝试分开记。与本地精简共享保持期：发布、尝试或宿主压缩后，至少 4 次真实工具工作请求，历史增长达到 `max(5000 字符, 15%)`，才再次自动摘要。只有真实工具工作计入工作数。

开启 Pi auto-compaction 时，令容量线 `T = 窗口 − Pi 解析的 reserve`、缓冲 `B = max(1024, 5% × T)`：

- OCC 在 60%T 等待、72%T 就绪、低于 52%T 退出等待。三次工作后未就绪可释放本地摘要；达到条件可重新评估，每次外部请求最多一次实际尝试。
- 达到90%T后不再启动OCC或本地prune；这是软交接，不阻止自然增长。实际用量超过T才由Pi容量压缩接管；OCC候选仍须留2B余量。
- 关闭 auto-compaction 时按模型窗口评估经济门槛；手动和必要容量恢复始终可用。

成本权重为普通输入∶输出∶缓存输入 **1∶5∶0.1**，考虑前缀变冷、输出上限与剩余窗口。取得 4 个不同成功工具轮次的增长观察后，估计可复用次数，超过回本所需次数才摘要；金额以 provider 账单为准。

`compactionSummaryMaxTokens` 在 Pi 与模型限制内生效，覆盖原生手动、阈值、溢出及 OCC 摘要；触及上限导致截断时保留原历史。OCC 用同一 cap 做容量/成本预检，并通过 customInstructions 请求默认约 16,384 输出 tokens 的软目标；软目标只影响 OCC 自己的请求，普通原生压缩保持 Pi 原样。模型输出上限未知且显式 cap 缺失时，OCC 提示 `unknown-output-limit`。

## 保护与状态

用户要求、错误、显式保护、当前 goal 和恢复引用按来源保留。源编辑、保护过大、归档失败、后台进程运行或结果变大均可阻止发布，包含 Pi 普通压缩的保护检查。

维护完成只恢复仍欠下且有效的 goal 续跑；暂停、已接受输入和取消状态会重新核对。取消会清掉候选和续跑债务，拒绝时保留拒绝原因。

prune 用量统计当前加载以来已报告的额外摘要输入与输出，拒绝候选同样入账；切分支重置，金额以 provider 报告为准。OCC 状态区分 compacting、compacted、cancelled 和 not compacted，调度只看状态本身。

远端加密路径见[远端压缩](codex-compaction.md)。来源与许可见 [NOTICE](../../NOTICE)和 [LICENSE](../provenance/condense/LICENSE)。
