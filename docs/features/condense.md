# 历史精简与恢复

condense 先保存可查询原文，再精简请求历史；模型摘要与机会式容量压缩（OCC）按各自门槛触发，Pi 普通手动/容量压缩仍由宿主管理。

## 设置与命令

配置位于 Pi `settings.json.contextPrune`，跟随宿主 agentDir。新安装不自动开启，不覆盖已有值；`/pruner status` 查看，`settings` 修改，`on/off` 启停，`now` 手动处理待摘要批次，`compact` 压缩已摘要调用链。

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| `enabled` / `opportunisticCompaction` | `false` | 自动精简总开关 / 需同时开启总开关的 OCC。 |
| `pruneOn` | `agent-message` | 最终回复边界处理，含 goal 中间回复。 |
| `minBatchChars` | `1000` | 确定性精简后达到门槛才考虑摘要；0 关闭门槛。 |
| `showPruneStatusLine` / `showOccStatusLine` | `true` | 额外摘要用量 / 最近 OCC 状态。 |

`off` 停自动精简，回读和既有图片上限仍可用；完全禁用需过滤入口。外部 pi-condense 改用内置入口时保留 settings、session 和 blobs；检测到已有 context_tree_query 会跳过本入口并警告。

## 候选处理

依次归档去重 → 确定性精简 → 对剩余正文判断摘要门槛 → 校验恢复证据与历史版本 → 发布。比较包含引用、占位符和包装的完整投影，只有整体净缩小才替换。

| 内容 | 安全条件 |
| --- | --- |
| build/test 日志 | 可识别且明确成功；exec_command 须确认退出码 0。运行中、未知、失败、read/search 和复杂未知命令不据此精简。 |
| edit/write 参数 | 完整成功调用组，参数合计至少 5000 字符，输入/输出可恢复且净缩小；保留最近工具交互。失败、未知或受保护组不处理。 |
| Fusion | 保留修改回执、路径和状态，仅精简安全命令日志，nested 分别索引。 |

参数的 5000 字符与 minBatchChars 是独立规则。有效 context_edit 使旧参数替换失效，重载不能改变同一历史结果。

摘要输入单批最多 24 次工具调用、65,536 字符，并根据摘要模型和会话回退模型的上下文容量预留提示词、输出空间；长正文保留诊断和首尾。自动和手动路径都在请求前按预算拆批，保留用户任务边界与工具调用顺序；同一工具阶段也可以分片。多调用批次放不下完整参数时拆分，单个超长参数才使用明确标记的原文片段；连最小片段都放不下时记录 input-budget，不请求模型，原文保留。

工具摘要和调用链合并都要求区分已观测结果与助手的推测，保留不确定性，关键代码条件和赋值原样引用；需要据此判断代码行为时，通过恢复接口核对原文。

子代理启动、等待、列表、消息、续跑、回答和中断的管理回执始终保留原文，不交给摘要模型改写状态。子代理正文结果与详细事件历史仍可归档和摘要。其他模型摘要仍是有损记录，不能替代验收或代码原文。

摘要请求最多并发 3 片，结果仍按原顺序归档、落盘和保存处理进度；后面的请求提前完成不会越过前面的片段发布。失败后停止调度并取消后续请求，切换会话或取消操作时取消全部未完成请求；重载只处理尚未提交的部分。并发窗口中已开始的请求可能产生费用。`/pruner now` 显示分批及部分完成状态。需要进一步合并摘要时使用 `compact`。agent-message 模式仍在最终回复时开始摘要，大输出仍在下一请求前落盘。

## 原文与分页恢复

归档在会话旁 `<sessionId>-blobs/`，目前不自动 GC。复制/清理 session 时一并考虑 blobs，读取证据不重放操作。

- 进程输出在显示截断/环形丢弃前捕获；小输出可留内存，超长或交付预算丢弃时落盘。每次返回绑定固定字节范围，后续 write_stdin 不改变旧结果范围。
- Pi bash fullOutputPath 在临时文件失效前导入；其他工具只能保存实际收到的内容，不能恢复 RTK/上游已丢文本。
- 原生 nested 使用 execution start/end 与 prepared 参数归档，父结果传播保护、错误、未完成和归档失败。缺失或失败捕获必须标不完整。

context_tree_query 返回历史证据；省略目标先列目录，再分页读取。

| 参数/字段 | 语义 |
| --- | --- |
| `toolCallIds` | 原 ID 或短引用，重复 ID 各次出现分别返回。 |
| `parentToolCallId` | 父工具的子归档；与另两个 ID 选择器互斥。 |
| `sourceEntryIds` | 历史来源条目，仅 output；与 toolCallIds 互斥。 |
| `component` | output / arguments；arguments 需指定 toolCallIds。 |
| `maxBytes` | 2048–32768，默认 32768；限制整个 JSON，含元数据/cursor。 |
| `cursor` | 绑定 session、目标内容版本和 component；普通增长可继续，分支切换目标消失则失效。 |
| `complete/eof` / `archiveComplete` | 分页进度 / 捕获完整性，两者不能混用。 |

分页按 UTF-8 安全边界切分，长行可继续，details 只含当前页。恢复保护按用户消息组处理，不把全部历史塞回请求。

## OCC 调度与成本

仅在最终回复后的空闲边界走 Pi 普通摘要路径；等待不计尝试。

- condense/OCC 共用等待与保持期；接近候选时延迟本地发布。发布、摘要尝试或宿主压缩后，至少 4 次真实工具工作请求及足够新历史才再自动处理。
- 预热、摘要、纯计划、轮询、失败、近期重复和回读不计工作。保持期不继续移除错误参数/保护读取，恢复页保持稳定；首次启用可能先还原旧占位符。
- goal 只恢复原本欠下的续跑，执行前复核已接受输入、暂停和目标；取消清掉旧续跑，不保证尚未处理输入立即打断维护。

开启 Pi auto-compaction 时，窗口 W、触发线 T=W-reserveTokens、缓冲 B=max(1024,5%×W)：

- 距 T 不足 B 时停止主动 OCC/自动摘要，保留原文继续归档；余量超过 1.5B 才退出让路。
- 候选前后均留 2B，含尾部、保护引用、摘要和固定开销；系统提示/工具定义不算可释放历史。
- 手动、宿主阈值和溢出保留原路径；关闭 auto-compaction 关闭容量让路。候选阶段使用宿主实际设置，SDK 仅内存设置未必可用于预检查。

成本门禁需已知价格，估算摘要、前缀变冷与后续 8 次请求收益；每次外部用户请求最多一次，goal 续跑不重置。此估算不保证真实账单或缓存收益。

本地精简后宿主用量未更新时，仅临时抵扣估计缩小量一半；已重估 context_edit 不重复抵扣，下一真实请求清除。手动与实际溢出不使用抵扣。

## 保护与失败

metis-occ-protected-v2 按来源保留用户要求、错误、显式保护与当前 goal；旧摘要保留恢复引用，避免递归包装，不从模型正文猜来源。未知格式/手动调用链保守保留，可能因此拒绝候选。

旧区成功归档或普通恢复结果可换精确位置引用，近期尾部与 protectedTools 保留；有效 context_edit 先投影，归档成功不授权隐藏用户、goal 或错误。

摘要变大、保护过大、归档失败、后台进程运行或历史变化均保留上下文；门禁也可拒绝 Pi 普通压缩。失败/取消清理候选并进入保持期，取消清掉欠下的 goal 续跑；安全拒绝后仍有效目标可继续。

## 状态与用量

prune 用量统计本次加载以来额外摘要，重复通知覆盖、切分支重置、未知价格不报金额。OCC 显示 compacting → compacted/cancelled/not compacted，等待和手动/宿主压缩不覆盖状态；隐藏仅关闭标记。

即使摘要候选被拒绝也记录用量；决策记录估计/实际大小和净变化。Footer Σ 使用标准 session 用量；Working 到 settled 后收尾，摘要中不预热，goal 提示以追加消息维持系统前缀。
