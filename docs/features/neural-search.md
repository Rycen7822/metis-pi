# Neural Search

Metis 维护的本地文件与内容搜索组件，参考 `@ff-labs/pi-fff` 0.11.0；不再依赖独立 Pi 插件的注册、配置或生命周期。底层 Rust 引擎源码、Linux 绑定和原生库构建发布也由 Metis 管理，不再依赖上游 FFF npm 包。当前交付 Linux x64 / glibc ≥2.31，Node 与 Bun 共用一套绑定。普通安装不需要 Rust/Zig 编译器，也不自动下载引擎；搜索在本机完成，不上传项目文件。名称不代表向量、embedding 或模型语义检索。

## 一个入口，按需加载

唯一工具为 **`neural_search`**，注册为 `deferred`。默认请求只带简短目录，不展开参数 schema；组件在普通会话启用 Pi 原生 `tool_search` 发现入口，**不会自动激活 `neural_search`**。受管子代理仍由其 profile 决定可用工具，本组件不越权补回被禁止的 `tool_search`。

1. 通过 `tool_search` 发现 `neural_search`，使其可以原生直接调用。
2. `action: "describe"` 配合 `target` 获取所需操作的精确参数。
3. 以 `action` / `params` 直接执行。codemode 仍是可选路径，不是必经入口。

```js
neural_search({ action: "describe", target: "find" })
neural_search({ action: "find", params: { pattern: "profile", path: "src/", limit: 10 } })
neural_search({ action: "grep", params: { pattern: "ProfileStore", path: "src/", context: 2 } })
neural_search({ action: "multi_grep", params: { patterns: ["ProfileStore", "profile_store"], constraints: "src/" } })
```

只有一个聚合工具被注册，操作参数按需读取。发现与激活后，保持激活的定义会进入后续请求；这不是每次调用后自动撤回。无原生发现入口的定制 SDK 宿主会收到提示，须加载并启用 Pi 内置 `tool_search`。不再提供旧工具名或替换内置 `find` / `grep` 的 override 模式。

| action | 能力 |
| --- | --- |
| `find` | 路径模糊查找、glob 约束、Git/常用度排序；`pattern` 用于模糊查找，精确路径或 glob 放入 `path`。 |
| `grep` | 单模式内容搜索；智能大小写，自动识别有效正则，纯文本可使用模糊回退。 |
| `multi_grep` | 多个字面量模式的 OR 搜索，保留原生匹配顺序，无需调用者拼接正则。 |
| `describe` | 只读取指定操作的帮助和 schema，不执行搜索或启动索引。 |

`find` / `grep` 保留 `path`、`exclude` 和有界分页；`find` 默认30条、每页最多100条，纯 glob 结果不按模糊低分截断。续页使用同一份完整快照，避免同分同修改时间的文件重复或遗漏；单次匹配超过10,000条会明确拒绝并要求缩小 `path`/`pattern`，不会把不完整快照伪装成完整分页。不同 find 快照合计最多缓存20,000条、分页游标最多200个；共享同一快照只计一次，超限淘汰最旧游标，失效后需重新查询。弱模糊结果按整份快照的最高分判断，不因进入后续低分页而中断；终止的弱结果预览不再返回误导性的 `hasMore=true`。这是条目预算，不是进程内存字节硬上限。`grep` / `multi_grep` 默认20条、每页最多50条；适配层保留原生整文件批次中的未展示行，再继续原生跨文件游标。内容游标不建立全量文件快照：包括已缓存行在内的内容续页，若索引发生更新，会明确要求去掉 cursor 重新查询，避免按旧偏移重复或漏项；保守的索引写入（含重扫/分类等无实际排序变化的写入）也可能使它失效，`find` 的不可变快照不受影响。首次内容查询在原生读锁内捕获版本，不会因等待读锁的后台写入随后完成而误报过期；原生续页也在同一读锁内校验版本后才使用偏移。原生引擎每文件最多收集200条：达到上限会明确提示可能还有遗漏，并返回 `details.perFileLimitReached=true`，应缩小查询或读取该文件；这不表示能通过游标检出第201条之后的匹配。`grep` 支持 `caseSensitive`、最多20行上下文，并保留源行缩进。重叠上下文按文件和行号合并，实际命中优先显示为命中行；正文与限制状态由单、多个内容模式共用同一处理逻辑，遵守 Pi 默认的2,000行/50 KiB展示预算（另加截断提示），超限设置 `details.outputTruncated=true`；原生多行结果因潜在裁剪也会保守设置该标记，并另用 `nativeMultilineLimited` 区分原因。这不代表当前页文本完整，续页不会补回本页省略的文本；可降低 `context`/`limit` 重查或读取对应文件。`multi_grep` 用 `constraints` 过滤路径。返回的 cursor 是当前组件会话/操作的分页凭据，不能跨操作、会话或变更查询复用；以 `describe` 返回的参数契约为准。

## 配置与交互

只读 `<agentDir>/metis-pi.toml` 的 `[neuralSearch]`，不读项目覆盖、旧 JSON、旧环境变量或命令行开关。默认值和字段说明见 [参数指南](../../metis-pi-config.md#neuralsearch)。修改后 `/reload` 或重启。

- `enabled` 控制本组件；`mentions` 独立控制编辑器的 `@` 文件/目录补全，不激活模型工具。`@src/`、`@../`、绝对路径等目录导航交回宿主补全，保留其路径前缀与引用规则，不为导航启动主索引。触发字符属性可由 Pi 宿主写回合并结果，支持与 skill-mux 等自定义补全扩展按不同顺序加载。含制表符等空白的补全路径也加引号；同一会话切换工作目录后可使用新索引，旧会话的包装器仍保持失效。
- 其他扩展占用 `neural_search` 时，本组件不初始化命令、补全或索引；运行中检测到失去所有权后，已有集成停止工作并释放资源，直到下次有效会话启动。
- `/neural-search health` 查看索引/引擎/数据库状态；数据库已打开不代表健康，会区分可用、维护/降级、禁用与检查错误；`/neural-search rescan` 请求重扫。
- 默认禁止以文件系统根目录为搜索索引根；允许主目录索引并警告，可关闭。外部路径仍须遵守同样限制。
- 主目录索引可能消耗明显 CPU/内存；目录符号链接默认跟随，可按需要关闭。辅助根和分页状态有界，会话结束释放原生资源，晚到初始化不得重建已关闭实例。
- 数据库不可用时允许无持久化搜索，并报告原因，不修改或修复陌生数据库。超出容量上限的 LMDB 也保留原文件并报错，不自动删除 `data.mdb` 或 `lock.mdb`；普通库格式、历史关联键和保留期不变，无需迁移。
- Node/Bun 共用私有 ABI v7，符号链接选项不再需要绑定选择/回退。Rust 已收敛到 Metis 的 AI 搜索策略，移除了有 OR 漏匹配问题的内容 bigram 预过滤，但保留真实过滤、目录评分、本地搜索和有界 owned 字节缓存（不对工作区内容使用 mmap）。原生结果只传实际使用的显示/分页数据，未消费的分值细节、高亮坐标不属于公共 SDK；结果解码异常也由原生 owner 统一释放。引擎源码、绑定和库必须一起更新；升级或回退原生引擎后须重启 Pi，单独 `/reload` 不会卸载旧原生模块。
- 实时新增/重命名路径遵守初始扫描的符号链接和非工作仓库隐藏路径规则，Git 工作区中的隐藏文件仍支持。扫描分类使用独立输入并校验索引身份/内容版本后回写，不在长文件 IO 期间持索引写锁；未知扩展文件由二进制改写为文本后可以重新参与搜索。文件监视、Git 状态与常用度自动记录仍保留；仓库 config/config.worktree 改变状态语义时定向刷新，linked worktree 也监听公共 Git 目录中的共享配置，分离 Git 元数据目录时保留实际工作目录；不会把其他工作树的 index 或 FETCH_HEAD/config.lock 等普通活动都变成全量刷新。Git 降级诊断只有在全量刷新成功后才清除，局部路径更新成功不足以证明已全部恢复。就绪状态覆盖目录监听订阅确认和首轮 Git 状态/常用度初始化尝试；目录扫描/提交失败会报告致命错误；监听器或 Git 工作线程失败不会丢弃已建好的索引，而是返回可搜索的部分状态并提示监视不可用或元数据不完整，可用 rescan 重试。前端等待超时仍可返回明确标注为不完整的当前结果。被冷却窗口限制的忽略规则/事件丢失重扫会保留请求后重试，不再静默丢弃。
- 辅助索引只按同一扫描根复用，不借用祖先索引：Git、隐藏目录与忽略规则依赖扫描根，父索引的覆盖范围不能代表子项目。缓存闲置时有数量上限，并由一个不阻止进程退出的定时器在空闲5分钟后主动释放；过期根下次查询需要重新扫描。并发执行中的租约可暂时超出缓存数量，释放后立即收敛，不是进程内存硬上限。已过期的游标直接报错，不为即将拒绝的续页重新建立索引。
- 数据库路径在读取全局配置时一次解析，仅主索引使用排序/历史数据库；辅助索引始终省略两个路径，不抢占主索引数据库，也不触发主索引的数据库失败警告或禁用状态。主索引数据库无法打开时，重试明确移除两个路径，显式配置也不会泄漏到无持久化重试中；扫描选项仍共享。
- 绑定成功导入的 promise 按模块位置保留在带版本号的进程级缓存中，避免 Bun `/reload` 重新导入原生模块；导入失败不永久缓存。索引实例仍按会话/工作目录单独释放，未改为全局实例。**更新原生引擎后需重启 Pi**，仅 `/reload` 不会卸载进程中已加载的原生库。
- `exclude="**/*"`、`exclude="!**/*"` 等全范围排除会排除整个搜索根，不等同于没有过滤条件。正向 `path="**/*"` 则表示整个搜索根。
- 覆盖主目录的警告统一按真实路径判断，包括主目录的上级目录和符号链接别名；这只统一提醒与状态显示，不扩大原有扫描拒绝规则。
- 请求取消会立即停止该请求对索引初始化的等待，不会销毁其他请求共用的索引；晚到的辅助租约仍会释放。底层同步检索本身不能在执行中由 JS 信号即时打断；零匹配查询仍优先扫描完整候选集，内部时间预算不是硬墙钟上限。
- 首次扫描超过等待时间后可继续查询已有索引，但结果会明确提示扫描尚未完成，不能据此断言整个目录无匹配。
- `src/../src/` 等目录路径按文件系统路径归一化。本组件只支持 Linux，文件名中的字面反斜杠不转换；绝对路径首尾空白按真实路径数据保留，不会被裁剪后指向相似目录。已存在的绝对文件路径无论在主索引还是辅助索引中，都按字面文件处理，包括文件名里的 glob 元字符；include/exclude 共用这条规则；普通元字符使用原生字面字符类；含花括号的路径使用经完整解析链验证的重复替代组，在 glob 编译前完成转义解码，不把反斜杠放进花括号字符类而扩大匹配。逗号、括号、反斜杠、Unicode 和无扩展名名称都保留原字节；非现存文件的绝对 glob 仍作为模式。相对输入的外围空白仍作为填充；目录名首尾含空白时请使用绝对路径。含空格的实际目录使用独立索引，并在返回文本说明真实搜索根；覆盖索引不能表达该相对路径时不复用。
- 内容模式与文件过滤条件分离；字面量中的 `/api/users/`、连续空格等不会被当成路径过滤，路径和排除约束也不会在模糊回退中丢失，具体文件路径同样不扩展成全目录。无效正则（包括单独的 `?`、`*`、`+`）按字面匹配，只有实际识别为有效正则时才拦截纯通配表达式；空白查询仍拒绝。内容 needle 与过滤表达式独立传给原生引擎，不再拼成一个 token，也不做二次反斜杠解码；空白、反斜杠和字面 `type:rust` 仍是 needle 数据。NUL 输入明确拒绝，避免 C 字符串截断。普通单行 OR 继续使用原生逐行收集与分页；多个模式中只要有一个包含真实换行就明确拒绝，须拆成单独请求，不再把整组 OR 转成多行正则。
- 单个多行模式仍可独立查询，但原生引擎会合并连续命中，并在返回前把块裁到512字节。本组件不会把这些块伪装成完整逐行结果：有实际命中时返回 `details.nativeMultilineLimited=true`、保守设置 `outputTruncated` 并显示限制提示；这是潜在不完整标记，不是精确测得的裁剪量。多行模式的计数是原生块数，不是实际命中次数；没有下一页不表示裁剪部分已完整返回。应读取对应源文件核对。只有无歧义标识符可尝试模糊建议。
- `path`/`exclude` 中的 basename glob（如 `file*.ts`、`file?.ts`、`file[12].ts`）规范化为原生内容解析器能识别的 `./` 形式；直接使用原生 `constraints` 时可写 `./file*.ts`。
- 原生过滤语法中尚未实现的 `type:` 明确拒绝，不再静默扩大或反向排除范围；可改用 `path: "*.rs"` 或 `constraints: "./*.rs"` 等 glob。过滤语法按空白分词，不支持含空白的文件名/glob 过滤，也不支持 shell 引号转义；这类路径明确报错，不再伪装成“无结果”。可先搜索其实际所在目录，再用 `read` 读取确切文件。已确认存在的绝对文件在列表分词前先按字面识别，文件名内的逗号不会拆成多个排除条件。`exclude` 标量支持空白/逗号列表；数组项不再按内部空白拆成多个路径，无法编码的文件名会明确拒绝，列表扫描器识别嵌套花括号、字符类起始字面 `]` 和结构外转义，只在 glob 结构外拆分逗号；例如 `[],].txt`、`{{a,b},c}.txt` 均保持完整。`exclude`/`constraints` 字符串仍是原生过滤表达式，不是 shell 命令。
- 命中行和上下文行超过500字符时缩短显示；单行缩短或整页超出默认2,000行/50KiB预算，都会显示省略提示并设置 `outputTruncated=true`。游标只续传尚未显示的命中，不恢复已裁剪的行尾，应读取源文件核对。
- 终端显示前清理不可信控制序列和双向文本控制字符，再应用主题颜色；不改写原始工具参数或复制元数据。多模式搜索标题同时显示 `path` 和 `constraints`，避免隐藏实际 AND 范围。

## 从独立插件切换

在安装本次 Metis 版本时，从 Pi 的 packages 列表移除独立 `npm:@ff-labs/pi-fff`，再重载或重启，避免两套工具、补全与索引同时运行。本仓库开发不会自动卸载你的包或改写个人配置。

旧 `pi-fff.json`、`FFF_*` / `PI_FFF_*` 环境变量、`--fff-*` 参数和会话模式不被新组件自动导入。将仍需要的偏好手工放到 `[neuralSearch]`；旧文件不删除或改写。

底层 reader 容量控制改用 `METIS_NEURAL_SEARCH_LMDB_MAX_READERS`（默认1024，合法值至少126；无效设置使用默认值）。旧 `FFF_LMDB_MAX_READERS` 不再生效；如曾设置，请手工改名并重启全部数据库使用者。这不新增 TOML 偏好来源，也不迁移数据库格式。

默认状态目录是 `<agentDir>/metis/neural-search/{frecency,history}`。不自动借用、搬迁或改写旧插件及编辑器的 LMDB 数据库。如需复用已积累的排序数据，可明确设置 `frecencyDbPath` / `historyDbPath`，并自行确认其他使用者的并发访问和备份要求；它们是数据库**目录**，不是单个 SQLite 文件。

回退旧插件需要重新启用其 package 和原配置，不依赖对新组件状态做反向迁移。旧会话中已有的工具记录仍是历史，不注册旧工具的执行别名。

## 维护边界

- 入口：`extensions/neural-search.ts`。
- 自有实现、MIT 许可与来源记录：`src/neural-search/`。
- 冻结参考：`references/pi-fff/`，不随 npm 包发布，不被运行时代码导入。
- Rust 引擎源码和构建：`src/neural-search/engine/`，只纳入必要的搜索核心、查询解析、grep 与 C 接口，不包含上游其他应用入口。
- 随包原生库、来源校验和完整依赖许可：`src/neural-search/assets/`，与 TS 适配一起收在同一个模块目录中。
  `npm run build:neural-engine` 从自有源码编译，`npm run verify:neural-engine` 校验源代码、二进制、ABI 和许可；`prepack` 自动校验，CI 从源码重建。
- 唯一外部运行时桥接依赖是可选的 `ffi-rs`，需要本地搜索时不要省略可选依赖。
  缺少绑定/原生库或运行在未支持的平台，首次实际搜索明确报错，不为发现工具启动索引。
  开发验收须使用真实引擎；构建说明与继承的 Rust 单元检查见 [引擎维护指南](../../src/neural-search/engine/README.md)。
