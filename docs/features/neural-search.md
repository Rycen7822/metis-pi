# Neural Search

Metis 维护的本地文件与内容搜索组件，参考 `@ff-labs/pi-fff` 0.11.0；不再依赖独立 Pi 插件的注册、配置或生命周期。底层仍使用固定版本的 FFF Rust 原生引擎及 Node/Bun 绑定，搜索在本机完成，不上传项目文件。名称不代表向量、embedding 或模型语义检索。

## 一个入口，按需加载

唯一工具为 **`neural_search`**，注册为 `deferred`。默认请求只带简短目录，不展开参数 schema；组件在普通会话启用 Pi 原生 `tool_search` 发现入口，**不会自动激活 `neural_search`**。受管子代理仍由其 profile 决定可用工具，本组件不越权补回被禁止的 `tool_search`。

1. 通过 `tool_search` 发现 `neural_search`，使其可以原生直接调用。
2. `action: "describe"` 配合 `target` 获取所需操作的精确参数。
3. 以 `action` / `params` 直接执行。codemode 仍是可选路径，不是必经入口。

```js
neural_search({ action: "describe", target: "find" })
neural_search({ action: "find", params: { pattern: "profile", path: "src/", limit: 10 } })
neural_search({ action: "grep", params: { pattern: "ProfileStore", path: "src/", context: 2 } })
neural_search({ action: "multi_grep", params: { patterns: ["ProfileStore", "profile_store"], constraints: "src/" } })
```

只有一个聚合工具被注册，操作参数按需读取。发现与激活后，保持激活的定义会进入后续请求；这不是每次调用后自动撤回。无原生发现入口的定制 SDK 宿主会收到提示，须加载并启用 Pi 内置 `tool_search`。不再提供旧工具名或替换内置 `find` / `grep` 的 override 模式。

| action | 能力 |
| --- | --- |
| `find` | 路径模糊查找、glob 约束、Git/常用度排序；`pattern` 用于模糊查找，精确路径或 glob 放入 `path`。 |
| `grep` | 单模式内容搜索；智能大小写，自动识别有效正则，纯文本可使用模糊回退。 |
| `multi_grep` | 多个字面量模式的 OR 搜索，保留原生匹配顺序，无需调用者拼接正则。 |
| `describe` | 只读取指定操作的帮助和 schema，不执行搜索或启动索引。 |

`find` / `grep` 保留 `path`、`exclude` 和有界分页；`find` 默认30条、每页最多100条，纯 glob 结果不按模糊低分截断。续页使用同一份完整快照，避免同分同修改时间的文件重复或遗漏；单次匹配超过10,000条会明确拒绝并要求缩小 `path`/`pattern`，不会把不完整快照伪装成完整分页。不同 find 快照合计最多缓存20,000条、分页游标最多200个；共享同一快照只计一次，超限淘汰最旧游标，失效后需重新查询。弱模糊结果按整份快照的最高分判断，不因进入后续低分页而中断；终止的弱结果预览不再返回误导性的 `hasMore=true`。这是条目预算，不是进程内存字节硬上限。`grep` / `multi_grep` 默认20条、每页最多50条；适配层保留原生整文件批次中的未展示行，再继续原生跨文件游标。原生引擎每文件最多收集200条：达到上限会明确提示可能还有遗漏，并返回 `details.perFileLimitReached=true`，应缩小查询或读取该文件；这不表示能通过游标检出第201条之后的匹配。`grep` 支持 `caseSensitive`、最多20行上下文，并保留源行缩进。重叠上下文按文件和行号合并，实际命中优先显示为命中行；正文与限制状态由单、多个内容模式共用同一处理逻辑，遵守 Pi 默认的2,000行/50 KiB展示预算（另加截断提示），超限设置 `details.outputTruncated=true`；原生多行结果因潜在裁剪也会保守设置该标记，并另用 `nativeMultilineLimited` 区分原因。这不代表当前页文本完整，续页不会补回本页省略的文本；可降低 `context`/`limit` 重查或读取对应文件。`multi_grep` 用 `constraints` 过滤路径。返回的 cursor 是当前组件会话/操作的分页凭据，不能跨操作、会话或变更查询复用；以 `describe` 返回的参数契约为准。

## 配置与交互

只读 `<agentDir>/metis-pi.toml` 的 `[neuralSearch]`，不读项目覆盖、旧 JSON、旧环境变量或命令行开关。默认值和字段说明见 [参数指南](../../metis-pi-config.md#neuralsearch)。修改后 `/reload` 或重启。

- `enabled` 控制本组件；`mentions` 独立控制编辑器的 `@` 文件/目录补全，不激活模型工具。`@src/`、`@../`、绝对路径等目录导航交回宿主补全，保留其路径前缀与引用规则，不为导航启动主索引。触发字符属性可由 Pi 宿主写回合并结果，支持与 skill-mux 等自定义补全扩展按不同顺序加载。含制表符等空白的补全路径也加引号；同一会话切换工作目录后可使用新索引，旧会话的包装器仍保持失效。
- 其他扩展占用 `neural_search` 时，本组件不初始化命令、补全或索引；运行中检测到失去所有权后，已有集成停止工作并释放资源，直到下次有效会话启动。
- `/neural-search health` 查看索引/引擎/数据库状态；`/neural-search rescan` 请求重扫。
- 默认禁止以文件系统根目录为搜索索引根；允许主目录索引并警告，可关闭。外部路径仍须遵守同样限制。
- 主目录索引可能消耗明显 CPU/内存；目录符号链接默认跟随，可按需要关闭。辅助根和分页状态有界，会话结束释放原生资源，晚到初始化不得重建已关闭实例。
- 数据库不可用时允许无持久化搜索，并报告原因，不修改或修复陌生数据库。
- 已处理固定引擎版本中的分页偏移、OR 内容预过滤漏匹配和 Bun 符号链接选项问题。为保证结果完整，关闭了有漏匹配风险的内容索引预过滤，仍使用本地原生搜索和 mmap 缓存。目录约束使用明确的 glob，避免相同名字的文件改变目录查找结果。
- 辅助索引只按同一扫描根复用，不借用祖先索引：Git、隐藏目录与忽略规则依赖扫描根，父索引的覆盖范围不能代表子项目。缓存闲置时有数量/TTL 上限；并发执行中的租约可暂时超出缓存数量，释放后立即收敛，不是进程内存硬上限。已过期的游标直接报错，不为即将拒绝的续页重新建立索引。
- 数据库路径在读取全局配置时一次解析，仅主索引使用排序/历史数据库；辅助索引始终省略两个路径，不抢占主索引数据库，也不触发主索引的数据库失败警告或禁用状态。主索引数据库无法打开时，重试明确移除两个路径，显式配置也不会泄漏到无持久化重试中；扫描选项仍共享。
- SDK 成功导入的 promise 按绑定策略保留在带版本号的进程级缓存中，避免 Bun `/reload` 重新导入原生模块；导入失败不永久缓存。索引实例仍按会话/工作目录单独释放，未改为全局实例。
- `exclude="**/*"`、`exclude="!**/*"` 等全范围排除会排除整个搜索根，不等同于没有过滤条件。正向 `path="**/*"` 则表示整个搜索根。
- 覆盖主目录的警告统一按真实路径判断，包括主目录的上级目录和符号链接别名；这只统一提醒与状态显示，不扩大原有扫描拒绝规则。
- 请求取消会立即停止该请求对索引初始化的等待，不会销毁其他请求共用的索引；晚到的辅助租约仍会释放。底层同步检索本身不能在执行中由 JS 信号即时打断；零匹配查询仍优先扫描完整候选集，内部时间预算不是硬墙钟上限。
- 首次扫描超过等待时间后可继续查询已有索引，但结果会明确提示扫描尚未完成，不能据此断言整个目录无匹配。
- `src/../src/` 等目录路径按文件系统路径归一化。Windows 相对路径的原生分隔符先统一为 `/`，POSIX 文件名中的字面反斜杠不转换；绝对路径首尾空白按真实路径数据保留，不会被裁剪后指向相似目录。已存在的外部绝对文件路径优先按字面文件处理，包括文件名里的 glob 元字符；它们使用经原生引擎验证的精确 glob，而不是 shell 反斜杠转义或单项花括号；成对及嵌套花括号在字符类内部额外转义，避免被原生预展开后命中其他文件。逗号、括号、反斜杠、Unicode 和无扩展名名称都保留原字节；非现存文件的绝对 glob 仍作为模式。含空格的实际目录使用独立索引，并在返回文本说明真实搜索根；覆盖索引不能表达该相对路径时不复用。
- 内容模式与文件过滤条件分离；字面量中的 `/api/users/`、连续空格等不会被当成路径过滤，路径和排除约束也不会在模糊回退中丢失，具体文件路径同样不扩展成全目录。普通字面量及正则失败回退共用编码路径，字面反斜杠用十六进制原子传给正则引擎，避免原生 `\\n` 二次解码改变内容。普通单行 OR 继续使用原生逐行收集与分页；多个模式中只要有一个包含真实换行就明确拒绝，须拆成单独请求，不再把整组 OR 转成多行正则。
- 单个多行模式仍可独立查询，但原生引擎会合并连续命中，并在返回前把块裁到512字节。本组件不会把这些块伪装成完整逐行结果：有实际命中时返回 `details.nativeMultilineLimited=true`、保守设置 `outputTruncated` 并显示限制提示；这是潜在不完整标记，不是精确测得的裁剪量。多行模式的计数是原生块数，不是实际命中次数；没有下一页不表示裁剪部分已完整返回。应读取对应源文件核对。只有无歧义标识符可尝试模糊建议。
- `path`/`exclude` 中的 basename glob（如 `file*.ts`、`file?.ts`、`file[12].ts`）规范化为原生内容解析器能识别的 `./` 形式；直接使用原生 `constraints` 时可写 `./file*.ts`。
- 原生过滤语法按空白分词，不支持含空白的文件名/glob 过滤，也不支持 shell 引号转义；这类路径明确报错，不再伪装成“无结果”。可先搜索其实际所在目录，再用 `read` 读取确切文件。`exclude` 标量支持空白/逗号列表；数组项不再按内部空白拆成多个路径，无法编码的文件名会明确拒绝，已有逗号列表/花括号 glob 语法仍保留，字符类（如 `[,]`）内部的逗号不参与列表拆分。`exclude`/`constraints` 字符串仍是原生过滤表达式，不是 shell 命令。
- 终端显示前清理不可信控制序列和双向文本控制字符，再应用主题颜色；不改写原始工具参数或复制元数据。多模式搜索标题同时显示 `path` 和 `constraints`，避免隐藏实际 AND 范围。

## 从独立插件切换

在安装本次 Metis 版本时，从 Pi 的 packages 列表移除独立 `npm:@ff-labs/pi-fff`，再重载或重启，避免两套工具、补全与索引同时运行。本仓库开发不会自动卸载你的包或改写个人配置。

旧 `pi-fff.json`、`FFF_*` / `PI_FFF_*` 环境变量、`--fff-*` 参数和会话模式不被新组件自动导入。将仍需要的偏好手工放到 `[neuralSearch]`；旧文件不删除或改写。

默认状态目录是 `<agentDir>/metis/neural-search/{frecency,history}`。不自动借用、搬迁或改写旧插件及编辑器的 LMDB 数据库。如需复用已积累的排序数据，可明确设置 `frecencyDbPath` / `historyDbPath`，并自行确认其他使用者的并发访问和备份要求；它们是数据库**目录**，不是单个 SQLite 文件。

回退旧插件需要重新启用其 package 和原配置，不依赖对新组件状态做反向迁移。旧会话中已有的工具记录仍是历史，不注册旧工具的执行别名。

## 维护边界

- 入口：`extensions/neural-search.ts`。
- 自有实现、MIT 许可与来源记录：`src/neural-search/`。
- 冻结参考：`references/pi-fff/`，不随 npm 包发布，不被运行时代码导入。
- 引擎依赖：可选的 `@ff-labs/fff-node` / `@ff-labs/fff-bun` 0.11.0；平台支持由引擎二进制决定。缺少对应绑定时首次实际搜索明确报错，不影响其他 Metis 功能的安装；需要本地搜索时不要省略可选依赖。开发验收应使用当前平台的真实引擎，不能以 mock 结果替代平台运行证据。
