# 子代理生命周期

父会话的 scope 标识所属子代理和任务。关闭或重载父端只断开连接，已接受的工作继续运行。重新打开父会话可读取保存的结果；后续任务由 `subagents_followup_task` 显式创建。

## 空闲与中断

后端连续 30 秒没有活动、排队或等待输入的任务后，排空请求，停驻已确认清理的执行进程并退出。历史、结果和待投递通知仍然保留。后续调用可按需启动后端；`subagents_followup_task` 以保存的子会话为起点，仅处理新输入。

中断会停止当前任务，文件修改保持原状。清理待验证的执行进程仍占用容量；进程归属明确后才自动清理。Linux / WSL 由进程 guard 跟踪后代，Windows 使用 Job Object。跨工具的写入隔离需使用独立工作区或操作系统沙箱。

## 输入与结果投递

| 状态 | 如何处理 |
| --- | --- |
| 输入已接受 | 可能仍在队列里。中断后标记为 `not_consumed` 的输入，需要时显式重发。 |
| 结果待投递 | 用 run ID 调用 `subagents_wait_agent` 或 `subagents_agent_result`。父端保存收据后确认投递。 |
| 结果已投递 | 可继续按 run ID 读取和分页。 |
| 写入操作的结果未知 | 重试时，操作 ID 和参数需与首次请求完全一致。 |

等待指定名称时会锁定当时的 run。回答与已投递的问题绑定；过期回答会被拒绝。任务结束通知可能在后续模型请求中交付；通知确认由收据路径负责，转录查看保持只读。

## 环境与配置变更

子代理继承 HTTP(S)、ALL 与 NO_PROXY 的常见大写及小写环境变量，即使 `childEnv = []`。其他要透传的环境变量需显式列入 `childEnv`；profile 的覆盖优先。读写 profile 约束工具访问，操作系统资源由系统权限与沙箱控制。

后端在启动时读取容量、超时和 profile。更换配置或运行时前，先完成活动工作并确认清理。忙碌后端继续运行至退出，新配置在后端重启时生效；出现 `version_mismatch` 时，等待当前任务完成并在后端退出后重连。清理或投递状态未知时，先检查任务和收据，再决定重连或重试。
