# 子代理生命周期

父会话的 scope 标识所属子代理和任务。关闭或重载父端只断开连接，已接受的工作继续运行。重新打开父会话可查看保存的结果，不会启动模型或重放旧任务。

## 空闲与中断

后端连续 30 秒没有活动、排队或等待输入的任务后，排空请求，停驻已确认清理的执行进程并退出。历史、结果和待投递通知仍然保留。后续调用可按需启动后端；`subagents_followup_task` 从保存的子会话继续，不重放旧输入。

中断会停止当前任务，不会回滚文件修改。尚未验证清理的执行进程仍占用容量；如果无法确认进程归属，不会自动清除。Linux / WSL 由进程 guard 跟踪后代，Windows 使用 Job Object。跨工具的写入隔离仍需独立工作区或操作系统沙箱。

## 输入与结果投递

| 状态 | 如何处理 |
| --- | --- |
| 输入已接受 | 可能仍在队列里。中断后标记为 `not_consumed` 的输入，需要时显式重发。 |
| 结果还未确认投递 | 用 run ID 调用 `subagents_wait_agent` 或 `subagents_agent_result`。父端保存收据后才确认投递。 |
| 结果已投递 | 可继续按 run ID 读取和分页，不必重新执行任务。 |
| 写入操作的结果不确定 | 仅用相同操作 ID 与相同参数重试同一请求。不用新的 ID 重复提交。 |

等待指定名称时会锁定当时的 run。回答与已投递的问题绑定；过期回答会被拒绝。任务结束通知可能在后续模型请求中交付；打开只读转录不消费通知。

## 环境与配置变更

子代理继承 HTTP(S)、ALL 与 NO_PROXY 的常见大写及小写环境变量，即使 `childEnv = []`。其他要透传的环境变量需显式列入 `childEnv`；profile 的覆盖优先。读写 profile 约束工具访问，不约束扩展与子进程能访问的操作系统资源。

后端在启动时读取容量、超时和 profile。更换配置或运行时前，先完成活动工作并确认清理。`/reload` 不会替换忙碌的后端；出现 `version_mismatch` 时，等待当前任务完成并在后端退出后重连。如果清理或投递状态不确定，先查看任务和收据，不要删除账本或重新发起任务。
